# 字节 n-gram 快表：与 Qwen3.8 N-gram 的对照、容量与升级方向（2026-11-03）

实现：`scripts/ib_local/ngram_fast_table.py`（表）、`scripts/ib_local/train_gdn_fast_table.py`（接入 GDN）。
结果：`results/cgb_ngram_fast_table_20261103/README.md`（表单独）、`results/cgb_gdn_fast_table_20261103/RESULT.md`（接入后，三种子）。

## 1. 现状

表的做法：0 至 6 阶字节 n-gram，每阶 2 个哈希头，16 位指纹；每个槽存下一字节的 256 维分布，按本槽访问次数做 Kalman 写入（增益 max(1/(n+2), 1/256)），不被访问不衰减；碰撞时按计数淘汰；读出按精度（计数/(计数+1)/滚动 Brier 误差）合并各头各阶。表的全部动态只取决于字节流，CPU 先行推进，数组可放内存或 `np.memmap` 硬盘文件，GPU 上不放表。

接入 GDN：第 1 层前 Engram 式门控注入，输出端按位置学权重做几何混合。三种子在线预测（nats/字节，中位）：

| | 首读 A | 新文 B | 重访 A | 新文 C | 重访收益 | 速度 |
|---|---:|---:|---:|---:|---:|---:|
| GDN 对照 | 1.899 | 1.625 | 1.490 | 1.674 | 0.133 | 3.0 万 B/s |
| 快表单独（908 MiB） | 1.637 | 1.545 | 1.360 | 1.600 | | |
| GDN + 快表 | 1.487 | 1.384 | 1.112 | 1.448 | 0.249 | 2.3 万 B/s |

只测了训练流上的在线预测；冻结验证、长上下文与 LAMBADA 尚未带表评估。记忆量 908 MiB 对 82 KiB，不是同等状态预算的比较。

## 2. 与 Qwen3.8-Flash-Next N-gram 的对照

依据：技术报告 §2.3、§3.1 与官方 `config.json`。报告未给门控公式与 n-gram 阶数；门控按其引用的 Engram（Cheng 等 2026）写，标为推断。

| | Qwen3.8-Flash-Next | 本项目快表 |
|---|---|---|
| 单位 | BPE token（词表 248,320） | 字节（256） |
| 阶数 | `ngram_size: 3`；报告只说“以每个 token 结尾的短 n-gram” | 0–6 阶字节 |
| 覆盖原文 | 3 个 token，约 10–12 字节 | 最长 6 字节，约 1.5 个 token |
| 哈希头 | 每种 n-gram 8 个（`heads_per_ngram: 8`） | 每阶 2 个 |
| 表大小 | 约 2000 万行 × 2560 维，n-gram 参数 510 亿（`ngram_vocab_size_base: 20000000`、`ple_embed_dim: 2560`；20M×2560≈51.2B，与报告 51B 吻合） | 7 阶 × 2 头 × 65,536 = 92 万行 × 256 维，908 MiB |
| 行内容 | 学出来的向量，含义不预设 | 下一字节分布，含义固定（条件统计量） |
| 写入 | 预训练时梯度写入（Adam，无权重衰减），部署后冻结 | 活着时逐字节写入（逐槽 Kalman），无梯度，不依赖网络 |
| 碰撞 | 只靠 8 个独立哈希，交给学习消化 | 16 位指纹 + 按计数淘汰 + 精度加权读出 |
| 组合与注入 | key/value 投影（Muon）→ 上下文门（推断：σ(⟨norm h, norm W_k e⟩/√d)）→ 4 阶短卷积（`ple_conv_kernel_size: 4`）→ 残差 | 精度合成一个分布 → log p → 同式门控注入（无短卷积）+ 输出几何混合 |
| 位置 | 48 层中第 2 层（`ple_layer_ids: [2]`），为让主机内存预取与第 1 层计算重叠 | 4 层中第 1 层前，外加输出端 |
| 存放 | 主机内存，异步预取（地址确定） | 内存或硬盘 memmap，CPU 先行推进 |
| 训练时 | 微调框架开启下放即冻结表（`PLE_CPU_OFFLOAD=1`） | 训练即生活，表从不冻结 |
| 代价 | 每 token 几乎不增计算 | 256 万字节 CPU 约 20 秒，训练慢 22% |

Qwen 自己的结果：
- 放置位置影响小：平均分 无 45.44，第 1 层 47.30，第 2 层 47.94，第 25 层 47.40；分到多层无稳定收益。
- 表越大损失越低（1.585 → 1.553 / 1.541 / 1.534 / 1.526，20×–200× 词表），下游不跟随：MMLU-Pro 在 100× 最好、200× 回落；仅 C-Eval、CMMLU 持续上升。
- 总参数固定时用 MoE 专家换 n-gram 槽，下游无提升：两者承担不同容量。
- 试过无效：token 归一化压缩词表、各阶不均匀分配、按频率分区。

本质区别：
1. **慢记忆与快记忆。** Qwen 的表学全语料共性，部署后固定，学不到新东西；本表学这一个体自己的流，一直在写，130 万字节前的上下文仍能精确取回。一个生命体两种都需要。
2. **可学内容与固定内容。** Qwen 的向量含义由梯度决定，表达力强；本表存分布，地址和内容都不随网络学习漂移，适合长期保存，代价是表达力弱。
3. **覆盖长度差约一个数量级。**

可借鉴，按代价从小到大：注入后加 4 阶短卷积；加 8、12 字节两阶，覆盖接近其 3 个 token；每行在分布外加一个低维（如 32 维）在线梯度更新的可学向量，承载分布装不下的内容（只有这部分会让表与网络耦合）。Qwen 的教训同样适用：损失下降不等于泛化变好。

## 3. 容量：塞满了怎么办

表是固定容量的，每阶每头 65,536 槽。本次 256 万字节流里各阶不同上下文数：

| 阶 | 不同上下文 | 槽数倍数 | 最常见 65,536 种占出现次数 | 只出现一次 |
|---:|---:|---:|---:|---:|
| 1–3 | 190 / 4,957 / 32,013 | 0.0 / 0.1 / 0.5 | 100% | 3% / 24% / 31% |
| 4 | 112,811 | 1.7 | 98% | 39% |
| 5 | 269,362 | 4.1 | 87% | 46% |
| 6 | 498,629 | 7.6 | 70% | 53% |

现有兜底：
1. **按频率淘汰。** 撞上已占用的槽先把计数减 1，到 0 才接管；一个槽相当于在竞争者中做多数投票，占其访问过半的上下文不会被挤走。只出现一次的 6 字节上下文占 53%，最常见的 65,536 种占 70% 的出现，淘汰规则正好留下值得留的。
2. **两个哈希头。** 一个被挤走，另一个可能还在。
3. **按阶退回。** 高阶忘了，低阶还在，读出按精度合并，只变粗不变空。实测随槽数 2^16 → 2^14 → 2^12，首读 A 从 1.637 → 1.692 → 1.821，平滑变差。

缺口：被挤走的那一行直接重置为均匀分布，内容一点不剩；而且现有淘汰只看频率不看价值，出现不多但每次大幅改善预测的上下文也可能被挤走。

## 4. 升级方向（待定，用户另有想法，暂不实施）

1. **多路组相联。** 一个哈希地址对应 4 个槽，同组内挤走计数最小者；内存不变，实现简单。
2. **随寿命增长容量。** 表在硬盘上，可按经历长度翻倍扩容、重新哈希；手机百 GB 级闪存够上亿字节经历。只是推迟问题：无限流下任何有限表终会满。
3. **淘汰前先巩固。** 槽被挤走前，把内容交给慢记忆（GDN 权重或每行的低维可学向量），相当于海马到皮层；被挤走的只剩网络已学会的或无价值的。对应相容核心“选择性排出：有价值内容的删除概率趋近零”，并要求淘汰按价值而不只按频率。
