## 当前分配

| 位置 | 对象 | 原因与容量 |
|---|---|---|
| GPU常驻 | 神经参数、梯度、Adam状态、当前S/P、当前使用的关系/经历工作集、正在兑现的信用 | 参与每次前向或更新，留在GPU减少往返；30.5M FP32参数+梯度+两阶Adam约465 MiB |
| GPU热缓存 | autograd保存的热激活；递归轨迹以块边界保存 | 默认上限512 MiB；按底层分配计费，共享视图计一次；每个事件根据当前空闲显存再保留768 MiB余量缩小上限 |
| 系统内存 | 有界激活副本、当前窗口的表概率和资格收据、页缓存中的热n-gram页、归档的当前读取 | 默认激活副本128 MiB；达到上限后转入磁盘；原dtype与布局保留 |
| 本地磁盘 | n-gram六组memmap数组、SQLite经历/关系/引用/版本、原始文本、检查点 | 现行表230.5625 MiB，按地址访问；OS页缓存承接热页，当前窗口概率进入GPU |
| 本地临时磁盘 | 超出两级缓存的反传激活 | 原始字节临时文件，精确大小空闲块复用；同一未变更张量共享副本；上下文结束删除；每次扩展保留256 MiB磁盘余量 |

缓存预算描述被这些hook管理的合格激活。参数别名和小于64 KiB的张量沿用原设备，反传临时量与优化器工作空间由PyTorch管理。GPU的512 MiB与主存的128 MiB在事件开始按需使用。

n-gram是磁盘映射的可写数据：寻址和逐行在线更新在CPU执行，当前窗口的`T×256`读出才进入GPU。增加表容量主要增加磁盘与页缓存的工作集。checkpoint writer沿用已有的tensor-backed数组视图和分块压缩写入。独立可复用的内存snapshot仍保存独立数组副本。`flush()`在需要发布映射页时可用；原子身体检查点继续承担恢复承诺。

## 32层实测

来源：自然线cycle2601的原已训练权重，主干29,672,448参数、d256、32层、8头、MLP768、卷积4。材料为原OWT来源的实际字节。每种方式预热一次，再做3次同步计时，取中位数。计时为主干前向+完整反传；优化更新0、世界调用0。完整闭环的数值等价由单独的两轮事件测试覆盖。

| 窗口 | 状态保存/激活存储 | 秒 | CUDA峰值MiB | 单次写盘MiB |
|---|---|---:|---:|---:|
| 128 | 逐步状态，GPU | 0.2016 | 393.62 | 0 |
| 128 | 16步边界，GPU | 0.2118 | 273.72 | 0 |
| 128 | 16步边界，全部合格激活写盘 | 0.6862 | 247.52 | 157.91 |
| 128 | 16步边界，512 MiB GPU热缓存 | 0.2106 | 273.72 | 0 |
| 480 | 逐步状态，GPU | 0.2070 | 1140.84 | 0 |
| 480 | 16步边界，GPU | 0.2234 | 659.84 | 0 |
| 480 | 16步边界，全部合格激活写盘 | 1.2929 | 252.22 | 588.62 |
| 480 | 16步边界，128 MiB GPU+128 MiB RAM | 0.9108 | 355.28 | 311.54 |
| 480 | 16步边界，512 MiB GPU+128 MiB RAM | 0.2267 | 659.84 | 0 |

480窗口推荐配置比全部卸载方式快5.70倍；相对逐步状态保存在GPU的方式，显存峰值减少481 MiB，计时增加约9.5%。128窗口推荐配置比全部卸载方式快3.26倍。各组loss、最终状态、全主干参数梯度均经过逐项比较，实测梯度最大绝对差0。

480窗口的推荐配置实际使用GPU缓存511.75 MiB、RAM缓存1.88 MiB。缓存小到128 MiB时，同一计算写盘311.54 MiB，实测速度随搬运量下降；因此默认容量按这组测量选为512 MiB。

## n-gram实测

默认完整表：7种order、2个hash head、每池16384槽，合计230.5625 MiB。CPU内存版与磁盘映射版分别处理相同8192个真实字节，核对返回NLL、概率及所有六组数组。

| 存储 | 秒 | 预测输出SHA-256 |
|---|---:|---|
| RAM | 0.150510 | `434cc99fa00617c799bf8e23b1fb39d55f458bf0bf44bd3ee173faa1926acfd4` |
| memmap | 0.192986 | 同上 |

这是本机短段读写的计时，包含映射页的实际访问。大表持续运行时，工作集、局部性与系统页缓存共同决定I/O成本。分配方案保留CPU现有读写规则，由磁盘承载容量、内存缓存热页、GPU消费当前窗口的概率。

## 接入入口与复现

`run_mother_continuation.py`、`run_guarded_mother_continuation.py`、`run_native_preview_restore_comparison.py` 已接入以下运行参数：

```text
--activation-mode tiered --activation-gpu-mib 512 --activation-host-mib 128
--table-storage D:/<当前私有工作目录>/table
```

续行入口的激活溢出目录为`<output>/activations`，比较入口沿用`--world-activations`与`--policy-activations`指定目录或工作目录。`--activation-mode device`选择原设备路径，`disk`选择合格激活全部落盘的对照方式。运行时包装器、hook和缓存receipt作为派生资源排除出checkpoint；恢复时按当前设备配置重新绑定。

存储作用域覆盖反传，hooks只包围原生objective及policy两个普通autograd端口。多速率交接在观察到达与完整更新返回时让出执行，后继事件为恢复的计算提供当前有效作用域。该调度已用CUDA强制写盘跨交接验证。

```powershell
$env:OMP_NUM_THREADS='1'
$env:MKL_NUM_THREADS='1'
D:/conda_envs/vox/python.exe -m scripts.benchmark_native_activation_storage `
  --checkpoint scratch/cgb_wood_policy_use_16rounds_20261120/natural/run/body/last.pt.gz `
  --output scratch/storage_benchmark_20261122/backbone.json --ngram
```
