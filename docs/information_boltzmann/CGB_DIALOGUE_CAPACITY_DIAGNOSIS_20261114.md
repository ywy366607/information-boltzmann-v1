## 两处应先排除的结构混淆

### 1. 32字节不是句子边界

`language_navigation_kanli_v4e.py::EqualEngine`和当前继承的`v4k::LatentDraftEngine._film`按`max_utterance`循环，结束不检查句法或句末。等长窗口是11-04为避免不成熟stop_head频繁中断真实后果而明确采用的方案，不是本轮新发现的bug；本轮实测确认它仍在限制当前输出。因此不能拿固定截取32字节是否构成完整句子当作小模型语言能力判据，也不直接重开已失败的stop_head支线。

### 2. 当前问题条件只直接改变字节输出偏好

生产`navigation_question_context.py::QuestionContextBody.predict_observed`为：

`logits_t(q) = logits_t(0) + W_question q`。

固定输入前缀与原递推状态时，q不直接改变该调用的下一状态/隐藏激活。任意两字节i、j的log-odds偏移为`(Wq)_i-(Wq)_j`，不依赖位置或该处上下文。采样出不同字节以后，后续状态当然能间接受到影响；不能据此声称这个条件通道绝对不能形成有序语言。

这里是问题变量与语言执行之间的具体表达限制，扩大底座并不自动改变这条直连通道的形式。是否优先升级它，要结合下列同权重展开检查；不因看到线性就立刻新增网络。

### 3. 说话条件仍参与预测妈妈的开头

沿`world_learning_cycle.py`和`QuestionContextEngine._advance`核对：q在`_utter`之后仍启用，第一段objective将自身发话目标mask为0，给妈妈开头的目标计算语言CE；第一次`_advance`之后才清除q。因此同一个`question_to_logits`既用于自己的发话，也从预测妈妈开头的CE取得梯度，并非只由取证后的策略信用训练。

固定q的直接CE导数是`sum_t(p_t-onehot(y_mother_t)) q^T / N`；自身被mask的位置不贡献该直接语言梯度。该共享会怎样影响发话，需要结合实际更新方向核对，不能仅凭此公式声称与策略梯度必然相反。但这是原设计“同一语言头在说/听条件下用途不同”需要继续核对的具体角色混用，先于盲目扩容。当前运行不改。

容量参考：[TinyStories原论文](https://arxiv.org/abs/2305.07759)展示了简化语料上不足一千万总参数模型可形成连贯故事，说明语言质量强烈依赖数据与训练分布；不能将其直接当作本体953931参数在OWT上应当具备相同能力的证据，也不把名称中的“1M”当作统一总参数口径。本轮没有下载模型或改变数据源。
