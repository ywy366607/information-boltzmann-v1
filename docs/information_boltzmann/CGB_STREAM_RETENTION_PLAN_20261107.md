# 连续状态组织与生命期记忆：当前实验及主问题

**11-07不可逆生命史（用户原意优先）：** 同一生命体不存在“新建独立请求”，不只禁止清S，也禁止每道题恢复旧存档、撤销已发生经历、丢弃自己生成内容后回到发声前。出生时初始化一次；正常运行沿唯一时间线摄入→预测/作答→实际后果→记忆/学习→下一事件，所有层S、短卷积、pending、自听、经历、参数及优化器持续交接，计算窗只截梯度。故障恢复仅续接最近已提交状态，不按答案好坏回滚。研究者可逆分叉是外部反事实诊断，不能作为主个体的实际生活或持续能力验收。当前continued_answers虽题前不清S，但每题恢复同一源、生成分支不提交，仍属于可逆旁路；结果仅作冻结诊断，不称不可逆生命周期成绩。下一主协议须记录单调事件游标、上段终态→下段初态连续，以及生成也进入后续状态，不得用更好的独立请求分数替代。

**11-07状态原则纠正：** 持续个体的主会话永不人为重置。官方GDN把上一调用的S与短卷积缓存传给下一调用；计算chunk/BPTT边界不是状态清零边界，detach仅切图。新的独立请求若未提供旧cache才重新初始化。此前四层交替清S只是已完成历史干预，不能由“全脑不能reset”推出“必须交替清层”；预训练交替清S尚未实现/启动，现暂停新增该对照。主运行保持全部层S/卷积、经历、权重及优化器连续，用原有可学习遗忘/擦除/写入和选择性保留处理更新。当前GPU答题评估reset_native=False，只在冻结研究者分支间恢复同一源，并非生命会话的实际重置。

## 当前问题

在已经具备基础语言与取用能力的GDN上，固定S面对持续写入时，哪些未来仍有用的区别会被干扰、覆盖或遗忘？有限经历载体能否让后来的结果选择性巩固过去参与，并改善未来的保持、取回、再学习和行动？

目标是维持有限而有用的记忆，不是把无限历史全部永久保存。不能仅由上下文长就断言S必定失效；要实际测出干扰负载、所需区别的丢失、取用错误以及选择性保留的作用。长期保持、可检索内容、旧参与学习信用是不同角色，必须在同一个实例内连接起来。

## 第二步：已有能力的GDN上的长流巩固

完成状态组织比较后，回到已通过取用检查的预训练GDN。先复现原有能力和相同持续状态协议，再沿长流扩大干扰与保留跨度；不能把原底座已会的跨窗口取数算成新信用路径的成绩。

主要比较应保持同一身体、数据和资源边界，分别辨认：已有S保持；有限经历的取回；同样取回但切断旧原生重算导数；有导数且保留策略可更新。需要时才加入错配历史和选择性淘汰对照，不把全部开关同时改掉。

主要结果包括真实任务表现、同一内容的长依赖保持、干扰后的取回/再学习、知识变化后的更新及持续学习。NLL和梯度只作配套证据；记录状态/经历年龄、保留和释放的原因，确认后来的结果确实修正了对应的过去参与。几十万词元仍是有限长流实验，不把它写成无限期成功。
