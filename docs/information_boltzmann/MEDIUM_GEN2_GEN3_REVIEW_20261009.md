## 第三代目前的实际作用

`LocalHopfBranchPathway` 的分支/Cayley/合并能量恒等式以及 CK 小树余结合测试已通过。CLI 已有显式分支迁移入口。

实际调用位于 `plastic_ports.native_read`：先完成局部与时间读出，再对汇总 feature 做双分支线性变换；只把 main 送往 decoder，residual 只用于诊断后丢弃。每次从 `(feature, 0)` 开始。因此它目前适合作为独立的读出变换对照；原定第三代的介质结构重组仍需要物理接线。

修复的单一核心契约是：**分支必须改变实际局部传导/耦合，并在固定预算内保留完整状态；嫁接与剪切必须通过 evaluator 改变该算子。**

优先验收：

1. 在已声明的有限状态槽内执行分支和合并，保留 residual；field、三路 flux、时间及电导/STP 等辅助状态都有明确连续接口。重组前后原有信息不能因为右支路被丢弃而消失。
2. 将树节点绑定真实局部生成元/耦合和容量；剪切、嫁接改变可执行算子。树名变化或纯共轭坐标变换用作零效应对照。
3. 迁移时新增算子从精确 identity 启动，完整 logits、state 与基线一致；随后监督梯度能够改变通路。现有随机微小权重仅近似恒等。
4. 移出 compiled forward 中 `torch.allclose` 的 Python 条件；优先局部小块或有界低秩耦合。D=768 时逐 token 求解 1536×1536 矩阵会重现速度瓶颈。
5. 共享 aux 必须显式外置，或在合并时拒绝时钟/aux 不一致；不得静默采用左分支。

CK Hopf 代数与动力系统 Hopf 分岔是不同对象。当前线性反对称算子支持能量保持的分支变换；CLI 的 limit-cycle bifurcation 表述需要对应实际分岔方程和验收后再使用。
