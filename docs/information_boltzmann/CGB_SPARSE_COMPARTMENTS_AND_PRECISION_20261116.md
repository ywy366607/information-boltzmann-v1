# 共演化、功能隔室、稀疏计算与低精度：统一候选

2026-11-16。用户提出MoT/共演化、MoE、隔室、稀疏更新、自发专家及NVFP4的结合。本页是代码核对与下一阶段设计依据；没有改现行32层身体、预算优化器、主训练或原10417轮目标。主线仍是完整体自然文本生长，不能按此页重建/冻结/重置身体。

## 现行代码已经做了什么，缺口在哪里

- `fine_grain/mot_coevolve.py::MoTJointLayer`：切片/语言联合更新、写回原场。现行`past_present_coevolution.py`继承了双向共同状态，但保持因果时间，不把未来字节交给过去。
- 共演化`exchange`确实调用当前层的真实Q/K/V/O与MLP限制算子；目前Q/K/V/O子空间固定取前rank=32，MLP固定取前min(2rank, hidden)=64单元。这是固定计算子空间，不是内容路由。新增方向是让过去M和现在h共同决定使用哪些功能单元，不能把已有双向更新当新发明。
- `BudgetedAdamW`确实可以把局部gate压至0，但所有参与参数仍计算稠密梯度，m/v仍更新。Triton核仍load/store完整矩阵，连gate=0时也写回相同权重；当前是逻辑写入稀疏，不是块稀疏计算/存储。
- 64×64 tile是计算布局；四个32×32子块的双侧预算没有证明tile就是功能器官。运行中没有自发专家聚类/分裂/合并。

## 一条共同组织链

`条件(h, M) → 有限参与集合I → 共演化/主干执行 → 真实后果与后到资格 → 局部写入 → 修订组织及下一次参与`。

共演化提供情境及过去/现在的共同解释；路由决定算什么；局部证据决定怎样改；物理预算约束可驻留/可执行的规模。专家可定义为长期共同参与、在条件下功能相容的一组单元，而不是预先命名的语义专才。

第一候选物理单元是MLP的功能通路：同一隐单元的gate行、up行及down列共同构成一个可执行贡献。不要把任意矩阵tile误当完整通路。先在MLP研究路由，保留全部GDN S/P持续递推，避免为了省计算破坏永不reset的状态更新。

主干和经历解释应该使用同一参与选择及参数身份；只让经历工作区选块、主干仍全算，不会省去主干计算。起初可把分组当逻辑成员关系，不搬动/平均W或m/v；待有相容/冲突证据才共享、细分或合并。硬件块可固定，逻辑组合及参与可学习；完全不规则稀疏不一定快于小稠密矩阵。

### 必须同时保留的时序

- 前向未参与不是“观察到零梯度”。当前密集矩阵的逐张量时钟，改为真块稀疏后不能继续冒充每块都有一次观察。
- 本地观察次数随该块的真实梯度/资格参与增加，不按其他块的活动推进。`GenerationGradientFilter.lean::occurrence_clock_beats_time_clock`在其噪声模型下支持此区别。
- 学习参与集合必须包括当下参与和后到信用引用的旧参与。只用当前路由乘整包梯度，会错误丢掉窗口外资格。
- 旧资格、版本、S/P/M、优化器状态和磁盘身份必须随逻辑组织保留。分裂/合并不能让待结算的过去失去对应对象。
- 路由必须能再次招募旧块/未充分观察的块；单纯将当前冷块永久排除，会让它再也得不到恢复证据。

现有`GenerationCountedPopulation::local_keeps_group_total/local_ignores_outside`证明给定分组后的局部预算合同；`GenerationGradientFilter::no_shared_shrink_for_two_snr`证明其统计模型中不同信噪不能共用最优收缩。它们约束载体，不推出分组算法已实现或必然生成专家。

## 三种稀疏与显存要分别记账

| 稀疏位置 | 可省的东西 | 仍须保留/实现的东西 |
|---|---|---|
| 写入W | 真实权重变化、稳定块重复量化/失效 | 当前m/v和反向仍稠密；目前核也未跳过W存取 |
| 前向/反向功能块 | 选中路径的计算、激活、梯度 | 稀疏执行器和有效路由；全部专家的总权重仍存在 |
| 物理驻留 | GPU内同时保存的权重/矩状态 | CPU/SSD上的完整持存状态、预取/写回及带宽预算 |

更新冷而每次推理都用的块，不能仅凭冷却卸载。很少被前向招募的块，才适合按需加载；两者是不同坐标。SSD可扩大总容量，热集仍必须满足物理预算，延迟也计入完整事件。

当前N=31,263,168，FP32权重119.26MiB、Adam m/v 238.52MiB，权重+梯度+m/v约477.04MiB，不含激活、递推、待结算梯度和图池。FP32 m/v改为8-bit的理想净节省178.89MiB，另计scale/例外块；不是整机或整轮显存下降75%。现行实测峰值约2.8—3.0GiB，不能仅靠优化器状态量化就声称模型可放大数倍。

### weight decay

局部一致性门抑制噪声写入、双侧预算分配提案；decay作用于已有参数幅度，二者不是同一算子。当前真实更新为`-lr * gate * (allocation * adam_proposal + decay * W)`，保持时两项同时停止。未来可比较不同正则/范数约束是否让decay多余，现有证据不支持直接删除。

## NVFP4可以结合什么

实机为GTX 1650 4GiB，没有Blackwell原生NVFP4计算能力。可以研究低位宽存储/按需解量化，不能把Blackwell论文的算力倍数外推到此卡。当前更直接的容量候选是块式8-bit矩状态或带更新残差的低位宽存储；尚未接入现行预算优化器。

NVIDIA文档中的NVFP4用E2M1值、局部scale与全张量FP32 scale；格式一般以16元素分组，TE权重训练配方还使用16×16共享scale。64×64预算tile可以包含这些物理量化块，生物/功能隔室不必等于量化块。

可利用当前更新的性质：

1. 没有实际W变化的块保持量化缓存及版本，避免重做量化/写回。
2. 真正变化的块按局部范围量化，并保留FP32更新累加或误差反馈；小更新不能因反复低精度舍入而永久丢失。
3. 冷却不是参数不重要；量化位宽按对实际预测/后果的误差影响判定，不能仅按gate分配。
4. 保持/资格/累计统计先留FP32。对长期递推S/P，必须单独检验低精度累积漂移，不能当普通线性层权重量化。

### 量化与当前Lean更新合同真正相交的位置

若m被量化，每步实际为`m_t = beta*m_(t-1) + (1-beta)*g_t + e_t`，原精确EMA分解不再成立。设每块RMS量化误差界为epsilon_t，额外保留标量`q_t = beta*q_(t-1) + epsilon_t`，则真实近期均值满足

`RMS(recent) <= (RMS(stored_m_t) + beta^n*old_bound + q_t)/(1-beta^n)`。

这是三角不等式导出的可实现误差预算，不是已经加入Lean/Torch的功能。若做状态量化，必须把这个界或等效的真实误差累积带进冷却证据，避免将量化噪声误当方向变化/信号消失。只把m/v换成低位宽而原封不动宣称原精确合同仍成立是不正确的。

## 原方法与本体的关系

- [EMoE](https://arxiv.org/html/2310.10908v2)：从已有网络的隐含模块结构构造MoE、可不增加参数；给出功能组织的先例，不等于无穷生命期的在线自主分裂/合并。
- [RigL](https://proceedings.mlr.press/v119/evci20a.html)：在固定参数预算中动态修改稀疏拓扑；给出有限预算下连接可变的先例，不替代本体的资格、连续状态与真实后果。
- [8-bit优化器](https://arxiv.org/abs/2110.02861)：分块量化m/v节省状态；对本预算算子仍需数值/恢复及冷却证据的专门验证。
- [NVIDIA NVFP4配方](https://docs.nvidia.com/deeplearning/transformer-engine-releases/release-2.19/examples/fp8_primer.html)：支持分块精度及硬件布局；不自动给出专家组织或免高精度累积的训练。

候选顺序：保持当前充分生长不中断；需要下一次结构升级时，先用同一情境路由打通主干/共演化/后到资格/本地时钟，证明真块稀疏的资源收益及整圈用途；低精度先做可控矩状态，再视硬件决定FP4计算。不能为了安装MoE或NVFP4另丢掉已工作的闭环。
