## 实码定位出的估值与执行差别

`causal_use_value.settle` 的 C 收益使用 `posterior(cat(old_x, new_x), cat(old_y, residual))`，将新证据添加到排除查询本身后的旧支持。`shared_unknown_bindings.commit` 则执行实际 `revise → retain_constraints`，根据有限事实预算释放旧证据，之后更新 SQL 中同一未知项的支持。

沿同一真实事件核对四个分数：

- `initial`：行动前固定查询身份时的预测分数。
- `old`：真实学习后，以当前参数、旧支持重新评分。
- `append`：同一当前参数、旧支持加真实新证据评分。
- `committed`：同一当前参数、SQL实际提交的有限支持评分。

后三项使用同一查询目标与编码器，每次排除查询自身：

`actual_U_gain = committed - old = (append - old) + (committed - append)`。

前项是新证据增益，后项是实际释放/替换的代价或收益。`old - initial`单独记录参数及表示变化。实际新事实使用归档的source/action/outcome；另记实际特征与行动前预测特征的距离。

这一映射检验C奖励的“拿到有用信息”经容量竞争和真实写入后兑现多少。下一估值构造把同一个有限 U 放进预演和结算，保留三项分数用于辨别取证收益、替换影响和表示学习。
