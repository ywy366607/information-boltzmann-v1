## 同一个状态怎样过24层

连续状态布局为：

```text
Frame = 当前激活 × (24层原生cache × 经历库连续字段R)
单层cache = S[4,256,256] × q缓存[1024,4]
                            × k缓存[1024,4] × v缓存[1024,4]
```

单个词元与有界chunk共用这个cache布局；激活时间维T单列。记录的occupied、版本、槽位、读取时刻和模式属于当前事件的离散分支，不能伪装成普通实数可微坐标。

每层的共同转移：

1. 当前激活和R生成本次读取增量；只有第2/13层启用，其余为零。
2. 输入放置模式：增量先加到激活，原块再计算。输出放置模式：原块先计算，再加**由同一块前激活生成的**增量；不能偷偷改为用块后状态重新查库。
3. 本层终态只替换24层cache中的本层项，其他23层逐项保持。
4. 新激活交给下一层。同一次读取不覆盖R；真正的记录写入在后面的显式事件执行。

`untouched_cache`、`updated_caches_deriv`、`layer_step_deriv`证明该交接及其方向；`outside_ports_no_increment`固定两入口；`run_layers_deriv`、`all_24_layers_deriv`将局部native/hook导数沿真实层序组装。

`runAdmission`把待满足的条件列成**沿这一遍前向实际抵达状态的有限清单**：本层native导数成立；若处于原读取入口，hook导数也成立；然后进入下一层。没有把完整24层导数放在结论的前提中。但清单中实际FLA块与hook的条件还需要逐项实例化，不能把合同存在说成实际运行实现已通过。

## 原经历hook的三条来源

已核对当前 `LayerExperienceRecall.retrieve/attach`、`ExperienceMemory.read` 和读信用实现：

```text
当前块前激活 → 当前encoder → 查询及Top-k槽位
槽位的旧输入/边界 → 当前原生块重算 → 当前encoder
两者形成权重与值 → 加权和 → inlet projection → 原前向
```

在选中身份固定的可微分支上，每个读坐标的方向为：

`dRead = Σ_slot (dWeight·Value + Weight·dValue)`。

这包括当前查询、地址编码器、旧记录数据、旧块的当前参数重算、值编码器、入口投影各自的来源。`softmax_weight_deriv`和`selected_read_deriv`给出当前有限支持上的权重/值方向；它们不会把读权重直接当成原写入的责任。

**full/held的窄切口：** 若前向、路由和当前编码器导数相同，只把值方向中的旧原生重算分量切掉，则差值为 `Σ Weight·dValue_old_native`。`held_replay_leg_difference`证明这个代数差。它是当前取回重编码的信用，不自动等于“改变当年一次参与对今天产生的全部影响”。来源必须登记清楚。

null条目的值为零，但其logit通过softmax改变其他权重；不能删掉null后再把历史权重归一化回1。occupied掩码、clamp与归一化零范数各有分支，普通softmax证明只适用于满足其前提的当前支持。

## Top-k何时可以作为固定支持

`strict_support_locally_stable`证明：有限分数连续，并且选中集合与未选中集合之间有严格间隔时，小扰动不会改变支持。此时可以对固定槽位读程序求导。

截止处分数并列不满足该前提；重叠的invalid槽、合并、替换、版本更换、FIFO游标推进也需要自己的离散语义。定理不允许把它们一概detach以后仍称总导数。版本守卫和实际候选身份应保留，不能用新槽位的内容替代旧参与。

## 记录写入也是因果转移

当前代码在 `commit` 中把本次活动及局部边界保存到capsule，并更新source/action等有限表。`copy_tree(...detach())`只切断自动微分图，不表示“过去一次干预不会改变这些记录”。

因此要区分两种目标：

| 目标 | R的处理 | 能够声称的精确性 |
|---|---|---|
| 当前参数重新学习一个已给定的旧记录 | R固定，只求当前重编码路径 | 条件性重激活信用 |
| 追踪过去一次参与对今天的影响 | 捕获时将对应方向写进R，后续读取时一并使用 | 包含该记录路径的条件性事件信用 |

`record_write_deriv`证明覆盖写同时覆盖该槽方向，不把旧资格错配给新记录；`record_merge_deriv`证明固定本次计数时，均值合并也合并相应方向。来源仍是当时实际发生的活动，不把正确答案写回过去。

这些导数均须声明参数日程。若固定实际已经走过的参数日程，只扰动一次局部参与，它们是这个条件路径的信用；若还要对随后Adam和学习决策的变化求导，就必须进一步纳入参数及优化器敏感度。本方案尚未承诺后者，更不保存每次权重/优化器快照。

仅native方向有：

- S：24×4×256×256 = 6,291,456坐标。
- 三组卷积：24×3×1024×4 = 294,912坐标。
- 合计6,586,368坐标；全部用FP32时每方向25.125 MiB，两个方向50.25 MiB。

## 记录与联合输运续推：同一个资格程序

### 先区分旧作用和新参与

原单参数参考的递推是 `D(1,e)=D(1,0)+D(0,e)`。但把作用因子U逐列搬运时，必须使用**参数方向为0**的旧作用输运；若每列都调用`D(1,U[j])`，新参数源会重复进入每列。

现新增`layerTransport`、`hookedTransport`与`runTransports`，都沿**同一个实际前向到达的状态**执行，保留原第2/13层入口、全24层cache和R。

`joint_source_transport_split`证明：

```text
24层完整方向(初值e)
  = 24层完整方向(初值0) + 24层纯输运(e)
```

左边仍是此前已证的共同转移；第一项是本拍参数源，第二项搬运旧参与。主前向门控的B_main与胶囊重算直接参数源B_replay仍须按原来的调用标签分别登记；本轮没有把两者重新混成已覆盖。

`hookedTransportCLM`和`runTransportCLM`把这个纯输运程序构造成有限组合的连续线性算子。`run_transport_operator_apply`证明它逐步执行的正是`runTransports`，不是另假设一个未知的全身Jacobian。

### 记录的三种字段不能用同一种规则

再次核对`LayerExperienceRecall.attach/commit`和`ExperienceMemory.commit_episode`，同一槽位的真实规则为：

| 字段 | 值怎样更新 | 资格方向怎样更新 |
|---|---|---|
| `memory.source` | 按旧计数n取`(n·old+fresh)/(n+1)` | 相同计数、相同系数合并旧方向和到达方向 |
| `capsule.inputs` | 本次实际65个输入覆盖 | 本次对应输入方向覆盖 |
| `capsule.boundary` | 本窗口**开始时**捕获的本层S/卷积边界覆盖 | 使用开窗时捕获的方向，不能取提交时的live末态方向 |
| 其他槽 | 保留 | 保留 |
| `slot+version` | 合并或替换都使该槽版本+1 | 新记录绑定新版本，旧收据不再适用 |

`commitFields`写出这一个记录转移，`commit_fields_deriv`证明其方向也是同一个转移。`replacement_zero_count`、`commit_untouched_slot`、`committed_version_rejects_old`分别核对替换、局部性和版本守卫。

版本失效指旧记录收据不能直接当新记录使用，不是清零source混合中仍存在的历史效应：这部分按同样的均值系数进入新版本；被覆盖的旧胶囊边界则退出该字段。

`open_boundary_cannot_be_replaced_by_end`给出严格区别：若开窗与末态方向不同，二者写出的胶囊就不同。这不是数值上的近似问题，而是因果时刻接错。

### 待提交捕获也属于同一份作用基

一段窗口尚未提交时，需要有限的pending方向：开窗本层边界、65个本层输入、单独的pre-inlet寻址source。它们从各自真实捕获时刻开始，属于联合E的pending字段。

此后若U/V发生合并或换基，pending字段也必须一起变换，不能留一份旧基下的方向，再配新V提交。开窗以后发生的新参与，对已经捕获的开窗边界没有直接源；它仍可以影响后来输入或其他状态。

按两端口、两份FP32方向计算，这组pending字段的固定预算约**5.21875 MiB**，另计工作激活。它不是24层历史快照，也不保存参数、优化器或RNG。此前C=512的记录方向预算668 MiB／方向继续有效；这里补的是窗口内交接成本。

### 读取增益由内容腿和寻址腿共同决定

设w为真实softmax权重，v为当前编码器重算的胶囊值，s为包括温度及偏置的logit，`y=Σwᵢvᵢ`。新增`read_direction_centered`证明：

```math
dy=\sum_i w_i\,dv_i+\sum_i w_i\,ds_i\,(v_i-y).
```

因此`read_direction_gain`给出当前点的局部增益：

```math
\|dy\|\le\sum_i w_i\|dv_i\|+
             \sum_i w_i|ds_i|\,\|v_i-y\|.
```

第一项读旧内容，来自胶囊输入/开窗边界经过本层重算；第二项改变读的分配，来自当前query和存储source经编码器、归一化及温度缩放。不能只保留第一项，或者把“旧记录已detach”当成第二项不存在。

`address_score_gain`对`ds=(<dq,k>+<q,dk>)/temperature+dbias`给出具体范数上界。`read_record_budget_row`再将同一组记录的key/input/boundary误差与query误差接到上述读取上；输入是各局部算子的增益系数，当前记录槽预算和原来压缩的归属不变。

null候选必须留在同一个softmax中：它的v和dv为0，但`v−y=−y`，query改变它的分数仍会改变输出。不能删null后再把历史质量归一到1。使用字段预算时，null行的记录输入/边界系数为0，query分数路径仍保留。

这些式子只对当前固定支持和身份使用。支持切换、并列、归一化clamp边界及版本事件继续按实际分支处理；本轮没有把它们一律当光滑。

### 误差按字段流动，不按库大小统一放大

`RecordBudget`只存各槽key/input/boundary的标量误差，`commit_budget_certificate`证明它与`commitFields`同步：

- source误差按`n/(n+1)`和`1/(n+1)`组合；`source_mean_preserves_budget`证明共同预算不会被这次平均放大。
- inputs与开窗boundary采用其真实捕获误差，覆盖旧字段的预算。
- 未触及槽保留旧预算；若随后压缩在该字段丢了作用，另计该丢弃。

[压缩文件](../../lean/CGBAxioms/reviews/causal_tag_compression_20261108.lean)新增`fieldInsertCost`、`field_insert_defect_bound`与`field_insert_error_certificate`，针对**同一insertCode所选的同一丢弃项**，计算其在各字段投影π上的损失：

`字段新误差 ≤ 字段输运误差 + max归属 × ||π(丢弃作用)||`。

这没有换压缩规则或另造一个判断者；它让原来的U/V更新与稀疏记录交接共用一份可查误差账。字段未被真实写入，不代表压缩时也绝无损失，所以两笔账必须相接。

### 原生层与24层增益怎样组合

`native_partial_gain`从当前native微分的input/cache两条腿构造一个2×2局部增益。`layer_transport_budget`接上实际入口位置：输入注入同时影响本层输出与cache写入，输出注入只在这一层改变送往后层的激活。

`transport_gain_certificate`给出沿真实层顺序组成的标量保守上界。若资格用展开的Hilbert坐标，而Frame使用结构化乘积范数，`packedTransport`显式使用固定线性打包及逆映射；`packed_transport_exec`证明二者执行相同转移，`packed_transport_gain`把范数换算成本也写进标量界。不能悄悄把两种范数当成相等。

这个标量界是可组合的保守后备；每层opnorm并非已经在实际模型上测得的好界。工程候选优先用上述字段行界，避免每次复制记录都把整份误差乘一个粗糙大数。当前编码器/归一化、65位置native重算、MLP等局部增益仍须由已证算子的实际分支与布局给出，不能默认整圈L等于α或1。
