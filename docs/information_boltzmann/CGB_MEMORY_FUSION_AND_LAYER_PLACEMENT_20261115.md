## 结论与上一轮决定修正

**L32是未经层位比较的构造选择，不是已证最优层位。**上次解决了“经历仍只看L1”的浅层输入限制，同时把当前token中经历融合后的骨干计算压到只剩一个block。深内容读出与内容注入是两个问题；本实现还将两者绑定在同一端口，因此存在明确的权衡。

用户提到的中层有对应研究：[ROME](https://rome.baulab.info/)把部分事实回忆定位在中层MLP。这个定位可为候选层提供依据，但不是本身体外部经历注入的层位结论。

用户给出的新论文其实偏向早层：在相同专用容量下，视觉专用FFN放前1–8层Avg VQA45.0，放最后21–28层35.1，从零预融合编码器44.4。[原文§5.2、表3](https://arxiv.org/html/2611.17334v1#S5.SS2)。这是专用视觉容量的放置比较；对本身体的启发是让新信息获得专用处理和足够的后续共同计算，而非直接套用其层号。

## 当前实际注入

| 身体 | 字节快表 | 经历、内容意图及世界模型端口 |
|---|---|---|
| 原4层导航身体 | 输入L2（`inject_layer=1`，从0计数）＋最终logit混合 | 同样输入L2，读到L1输出 |
| 继承增长的旧32层身体 | 输入L2＋最终logit混合 | 仍输入L2；256↔128桥不改变它的深度 |
| 当前原生32层身体 | 输入L2＋最终logit混合 | 输入L32，读前31层处理的内容，事实宽256/潜128 |

旧`CGB_NGRAM_FAST_TABLE_20261103.md`将此位置写成“第1层前”，与当前保存/恢复路径及构造默认值不符；按上表说明实际导航身体，旧实验数字不改。

1. **字节快表**：CPU按0–6阶字节上下文读取下一字节分布。`train_gdn_fast_table.TableGDN.predict`把中心化`log p`投影成key/value，与当前位置hidden的归一化内积形成sigmoid门，将value加到L2残差；最终还有位置相关权重的`log p`混合。这条路径有内容相关注入门。
2. **经历**：`latent_navigation_v3.ExperienceMemory.read_encoded`以当前编码的归一化查询，对热源状态进行相似度检索，取最多8项；value主要是重编码后的经历action-state，不是原文字节。`latent_navigation.LatentNavigationBody.predict_observed`再执行`hidden += tanh(read_gain) * to_hidden(value)`。**寻址内容相关，整体注入幅度仍是一枚共享可学习标量；没有Qwen式的逐位置key/query注入门。**默认调用没有传null，因此有占用记录时会分配历史质量；“存在可选null接口”不能说成现行该入口已经使用它。
3. **意图**：在同一端口用当前query产生乘法gain和shift，受实际自听/世界输入的作用域控制；有内容调制。它与经历入口的共享标量不是同一个门。
4. **S/P**：各层P由各层query读取，拼接经共享投影进入原下一边界预演；每层S/P还参与自身物理递推。并非所有记忆都变成L32处的一次残差相加。

源码：`train_gdn_fast_table.py:58,89`；`latent_navigation.py:194,204`；`latent_navigation_v3.py:103–140`；`question_language_port.py`；`navigation_momentum_wood.py:20`。

## Qwen的实际实现及层位依据

[Qwen技术报告§2.3.1、表7](https://arxiv.org/html/2608.30320v1#S2.SS3.SSS1)比较浅、中、深层及多层。中深层也有竞争力，分到多层无稳定优势；选择L2还为了将主机表项预取与L1计算重叠。不能据此说“所有记忆必须在早层”。

[官方Transformers实现](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen4_exp/modeling_qwen4_exp.py)已能核对旧文的门控推断：

- bigram/trigram多头哈希，读学习向量，做key/value投影；当前残差内容决定取用门。
- 门控value再经归一化和因果短卷积后加入残差；四条残差流的门分别计算。
- `ple_layer_ids=[2]`通过`layer_idx+1`解释，确实是从1计数的第二层。

重要差别：我们的字节表行有“下一字节分布”的固定含义，Qwen的表行由训练学习表征；我们的经历行则是版本化真实事件及连续因果内容，不应合并成字节计数表。

## 注入是否可按多模态设计

本项目只有语言边界，但当前输入、重激活经历、意图和S/P来自不同机制、时间和不确定性。**按多源表征融合设计是可行的架构类比**：各来源先对齐到共享身体坐标，再按当前内容决定取用，真实后果更新相同通道。这个类比不将文本经历改称视觉模态，也不赋予它视觉论文里的已测收益。

更具体的设计问题是：从哪层得到可用query、在哪里加入召回、给召回多少后续计算、用什么内容门及身份约束。当前L32把前三个问题绑定成一个层号，必须在下一次结构比较中显式拆开检验。

## SSD优势已有哪部分、还缺什么

[Strata官方模型说明](https://github.com/Niko1221/Strata/blob/main/docs/MODELS.md#will-it-fit)与[实现参考](https://github.com/Niko1221/Strata/blob/main/docs/DETAILS.md#how-it-works)把大lookup表留SSD，每token仅读少量行；专家另分配在CPU/GPU。这里可复用的是稀疏可寻址存储，不是“把任意大网络全部放盘仍可免费全参训练”。

现行身体：

| 数据 | 当前位置与取用 | 大容量瓶颈 |
|---|---|---|
| 字节快表 | E盘memmap，CPU哈希读写；GPU仅收当前分布 | 已具备不随总表容量搬运GPU的性质 |
| 因果经历/关系档案 | E盘SQLite，65536条预算、512MiB上限，按身份载入热工作集 | 记录持存已做，后续仍须控制寻址开销 |
| 热经历 | GPU4096槽，当前编码器读8项 | 目前先编码/比较全部热槽，不宜按百万槽直接放大 |
| 冷关系寻址 | `causal_archive.best_relation`每批256条，逐批当前重编码与评分 | **显存临时量有界，但查询计算与扫描I/O随库容量增加；不具备n-gram直接寻址复杂度** |

下一存储升级应是“稳定ID与版本 → 有限候选寻址 → 当前编码器精排/重激活 → 少量GPU内容 → 后果沿原ID写回”。索引只是候选入口，不能替代真实证据，也不能把漂移的旧embedding当成永久正确的因果地址。无须为32层复制32份完整库。

## 下一实施决定

- 不在正在训练的身体上直接把L32改到L16：现有经历已按当前端口写入，热换会混合坐标与责任历史。
- 下次层位结构比较同时覆盖L8、L16和当前L32，分别记录同一查询的内容可读性与召回后整圈预测/行动收益；参数、数据、更新预算一致，所有候选都使用完整原闭环。不能以一次无训练端口平移或后验线性探针判定最优层。
- 优先于盲目扩表的是有预算的候选寻址和内容取用；层位和SSD存储是两个独立设计轴。当前正常初始化长跑继续积累语言基础，不冒充层位比较已经完成。

## 用户补充后的核心方案：经历专用计算在骨干内部融合

用户指出：只谈早层/晚层遗漏了论文的核心，即in-fusion与专用于视觉的容量。复核§4、§5：相同新增预算用在视觉专用分支优于直接加宽共享骨干；in-fusion让所有token继续经过共享参数，视觉token额外使用专用分支。它不是两套独立骨干。这个受控结果支持我们研究“来源专用＋共同计算”，而非只移动一个残差入口。

### 候选构造

**一次有限取回、一个临时经历工作集、共享算子加经历专用增量、同一真实后果更新。**不是每层复制一份经历库，也不为五相各建独立编码器。

1. **预取与持续身份。**在决策边界复用已有深层查询及绑定关系，从持存库取得有预算的真实经历，保留原ID、代际、版本和实际后果。当前字节的深层表征尚未产生前，不声称已用它完成早层预取。进入实际语言计算后，当前位置内容只对这批候选重新取用；后续边界再更新候选。
2. **保留角色，不先平均成一个action向量。**source、action、observed outcome及对应关系组成有角色的经历工作项；沿现有绑定/编码器处理，不把未观察到的后果混入事实。当前已有角色与证据结构可复用，不从头造一份新知识库。
3. **经历专用容量。**在早中层区间设置专用FFN增量，例如L8–15作为候选（不是文献确定的最优层）。对经历项m执行`m_next = m + F_shared(N(m)) + F_memory(N(m))`。语言h经过原共享GDN/FFN，只有经历项使用F_memory。共享投影/FFN同时作用于两类激活；因此不同于只给记忆加一段外接MLP后一次性相加。
4. **在融合中持续选择。**每个融合层用当前h形成query，对加工后的经历项做有null候选的内容取用，再通过逐位置、可按通道变化的门进入原GDN残差。经历项在融合区间内逐层加工，后续共享层继续整合。source标签只表示“取回的真实历史”，相关性、取用强度和组合由学习决定。
5. **保持时间和事实边界。**经历工作项不是新到达的外界token。它们经过共享静态投影/FFN；不将其依次灌进生产GDN的S冒充真实时间。生产S/P按实际自听、真实外界输入及原内部运动前进。临时工作向量不覆盖原观察，真实后果到达后才沿原共同U修订相应关系和参与。
6. **同一更新闭合。**实际回应损失、边界预测与原延迟行动结算通过取用路径学习共享参数、经历专用参数及编码器；原ID/版本负责信用回到本次实际参与。专用分支必须影响木的候选预演、火的实际表达、土的真实学习和下一次水的取用，不能只在旁路训练一个记忆重构头。

深层事实/世界模型接口可继续保留在L32；较早融合口和深层写入/结算口不必再用同一个层号。这样能够继承事实类型与坐标宽度，避免将已存L32特征直接改名成L16特征。新增参数及未结算参与仍须在完整存档/恢复中明确登记。

### 容量与比较

用256维、隐藏64的SwiGLU经历分支，每层`3*256*64=49152`参数，8层约393216参数，另计接口/门。候选来自已有8条证据预算；大档案仍SSD化。只为专用神经算子及本次工作项分配显存，不把档案变成稠密可训练大矩阵。实际训练峰值与吞吐须整机准入，不用参数量代替实测。

首要比较从“哪个层号好”改为同预算的三种完整闭环：当前召回入口、同等新增容量的共享计算、经历专用in-fusion。之后再在胜出的计算形式内比较层位。验证旧经历正确配对/错配/空取用对后续真实预测、学习和行动的影响，连同独立文本及重访/再学习曲线；不能只凭多了参数或NLL下降归因于经历。

以上是本项目的架构推演，不是视觉论文已经替我们验证的结果。本次登记方案，运行中的正常初始化身体保持原架构；未静默新增分支、重置状态或更换检查点。
