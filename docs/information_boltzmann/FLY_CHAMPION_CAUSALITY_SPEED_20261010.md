## 2. ALIF

- 首次加入（10 月 3–4 日，3000 步对照）：放电率 24%（仅 COBA）→ 14%（+ALIF）→ 约 1%（+ALIF+STP），验证 NLL 7.498 / 7.500 / 7.516 几乎相同。
- 冠军个体：β、τ_a 都在初始值 ±10% 内（未学动），27 个大类共享。只看 b>0.01 的 22% 神经元，阈值抬高中位数 4.2%，99 分位 26%。
- 四支柱协议下的分叉对照（`--disable-alif`，`scratch/fly_alif/`，续训 1024 token、5 次在线评估）：B 先测后学 NLL、A 重访、首次通过增益都在 ±0.01 内，
  放电率 2.57% → 2.86%。结论：在当前个体里 ALIF 只轻微压低放电，对学习、适应、保持无可测作用；原先压低放电的职责已由 STP 和抑制接管。

## 5. 提速：融合的确定性 incoming 前向

性能分析（`scripts/ib/profile_fly_champion.py`）：原实现中突触传递前向占推断 90%、训练 72%（PyTorch 取出 → 乘 → 分段求和，每步生成 2500 万长度中间张量，每次约 12.8 ms；同样的边 Triton 反向只要 3.3 ms）。

新内核 `_incoming4_fwd_kernel`（`information_boltzmann/core/triton_synapse.py`）：每个程序处理 4 个突触后行的全部 4 个延迟档，行内固定顺序累加（无原子加，确定），
突触前未放电的边跳过权重读取。仅在 CUDA、B=1、float32 时启用；`FLY_FUSED_INCOMING=0` 回到原算法。

| | 原来 | 现在 |
|---|---|---|
| 单拍突触传递（E+I） | 25.4 ms | 9.15 ms |
| 推断 | 4.87 token/s | 11.39 token/s |
| 训练 32 token 窗口 | 16.48 s | 8.71 s |
| 峰值显存 推断 / 训练 | 981 / 1844 MiB | 895 / 1843 MiB |

数值：真实连接组上相对误差约 1e-7，重复调用逐位相同；`test_incoming_synapse` 等 82 个果蝇测试通过。
每拍放电神经元约 2.8%，其出边约占全部边的 7%：真正的事件驱动前向还有数倍空间（需原子加或确定性归约设计）；训练中检查点重算使前向执行两遍。

### 5.1 继续加速：事件驱动 + 编译（同日）

| 步骤 | 单拍突触传递 | 推断 | 训练 32 token 窗口（预热后） |
|---|---|---|---|
| 原实现 | 25.2 ms | 4.87 token/s | 16.5 s |
| 融合 incoming 前向 | 9.2 ms | 11.4 | 8.7 s |
| 事件驱动前向（只沿放电神经元的出边，64 位定点整数原子加，结果确定） | 2.1 ms | 29.2 | 5.2 s |
| + 事件驱动权重梯度，学习器反向中直接累加到 `.grad` | — | — | 5.2 s（省掉逐拍的整段梯度张量） |
| + `torch.compile` 融合单拍逐元素部分（仅 CUDA） | — | **33.6** | 4.36 s |
| + 检查点重算时复用前向记录的突触电流（不再重算传递） | — | 33.6 | 3.80 s |
| + 对脉冲的梯度改为按段求和，并把权重梯度并入同一内核 | — | 34.0 | 3.07 s |
| + 事件驱动前向只遍历在 GPU 上压缩出的放电列表 | 约 0.8 ms | **46.2** | **2.90 s** |

开关：`FLY_FUSED_INCOMING=0`（原算法）、`FLY_EVENT_DRIVEN=0`（融合 incoming 前向）、`FLY_COMPILE_TICK=0`（不编译）、`FLY_REUSE_TRANSMISSION=0`（重算时重新传递）、`FLY_PULSE_RUNS=0`（原子加的脉冲梯度）、`FLY_EVENT_COMPACT=0`（逐行扫描的事件前向）。
`direct_edge_grad` 只在 `FlyBPTTLearner.observe` 的 `loss.backward()` 内开启；`torch.autograd.grad` 等用法仍按常规返回完整权重梯度。
峰值显存：推断约 1.5 GB（含一次性建表），训练约 2.2–2.3 GB。测试：`test_incoming_synapse`（新增直接累加测试）及果蝇学习相关共 100 个通过。
复用：每个 token 第一次前向时把每拍的突触电流（E、I 各一个 N 维向量）存下，检查点重算时按顺序取回，传递前向从 1.19 s 降到 0.62 s，峰值显存 2233 → 2519 MiB（32 token 窗口多约 290 MB）。重算的前向逐位相同；梯度与不复用时的差别和两次完全相同运行之间的差别同量级（约 1e-10 相对，来自反向其他部分的原子归约），测试 `test_checkpoint_recompute_reuses_transmission_exactly`。
对脉冲的梯度（必须稠密，ATan 代理梯度处处非零）：瓶颈不是读边，而是按突触后神经元随机取 g[post]（只读 post+w 为 1.1 ms/拍，加上取 g 为 3.5 ms/拍）；
神经元重新编号（空间 Morton、超类、RCM）都不能改善，每 32 条相邻边仍落在约 30 个不同的 32 字节扇区上——一个神经元的出边本来就散布全脑。
因此只去掉其他开销：边已按（延迟档，突触前神经元）分组，每条边只存 1 字节的块内段号（256 条边一块），代替 4 字节的 pre；
每段的部分和存一次，再按固定顺序合并（无原子加，逐位可复现）；同一次读到的 g[post] 顺带给出放电神经元出边的权重梯度。单拍 5.15 → 3.40 ms，已到取数下限。
事件前向：原内核逐行检查全部 16.5 万 × 4 个（延迟档，神经元），零脉冲时也要 0.97 ms/拍；现在先在 GPU 上把放电的槽压缩成列表（不与主机同步），
常驻程序只遍历列表，1.9 → 0.8 ms/拍，与原事件前向逐位相同。教训：Triton 内核里对同一地址先读后写零会竞争（读、写可能分到不同线程），清零改用单独的 memset。
测试：`test_run_sum_pulse_gradient_matches_autograd_and_is_bitwise_reproducible`、`test_compacted_event_forward_is_bitwise_identical_to_the_row_scan`；果蝇相关 113 个通过。
剩余（训练窗口 2.90 s）：突触传递反向 0.93 s（取数下限约 0.8 s）、单拍其余前向 0.76 s、其余反向与优化器和主机 0.85 s、传递前向 0.37 s；推断 46 token/s，传递前向占 49%。
