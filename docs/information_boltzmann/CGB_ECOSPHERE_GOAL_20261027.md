# 目标：第一个产出——生态球（2026-10-27 写定）

用户 2026-10-27："跑通这个生物大肠杆菌-世界联合（其实就是个生态系统）。然后给我一个可以持续运转无限步的实时生态系统，二维的就行，像游戏一样，我可以重置，可以放新的大肠杆菌，可以放食物。这样就是我们项目第一个产出，类似于生态球的东西。"

## Goal

一个在浏览器里实时运行、可无限运转的二维生态球：世界是已过准入门的 `rain_torus_w0`，生物是由选择生成、通过准入门的嵌套大肠杆菌；用户可以重置、放食物（在点上降雨）、放新的大肠杆菌、暂停与调速。

## 完成标准（逐条核验，不靠说）

1. **世界**是 Lean 实例（`axioms_torus`），模拟器由同一张表生成，速率与 Lean 逐条对拍；准入门 ADMITTED。✓（d0c4c59 / 8683b49 / cff2ec5）
2. **生物**结构由定理定（膜门控、全页泄漏 `leak_bound`、死亡 `dead_intake_is_physics`、分解 `corpses_must_go`），数值由选择定（`run_cgb_generate_nested.py`），模拟器（引擎与 GPU 精确内核）对拍通过。
3. 生物的**生命门**：Lean 层（感知、代谢）与执行层（排泄、选择性排泄、记忆、闭环优于致盲）通过；预言 O1–O4 按预注册检验并如实报告（不成立也写原因）。
4. **网页**：同一张表的 JavaScript 实现（世界 tau-leap dt = 0.05、生物逐事件精确 Gillespie、多个生物同一世界，每格至多一个、只能移入空格）；与 Python 对拍：同一状态下所有事件速率逐列一致（相对误差 < 1e−5），统计量（无生物世界的总食物轨迹）在误差内一致。
5. **无限运转**：页面持续运行，不因数值溢出或状态越界停下；死后尸体靠物理泄漏分解（G26c），雨永不停（世界的边界驱动）。
6. **交互**：重置；点击放食物（= 该处的雨，世界边界的刺激）；点击放大肠杆菌（= 用户作为外部世界把一个新个体放进空格，属介质之外的干预，页面上注明）；暂停、调速；显示每个生物的膜、储备、马达状态与存活时间。
7. 页面作为 Artifact 发布，链接与验收记录写入本文。

## 不在本轮范围（如实标注）

- **繁殖（分裂）**：当前 Lean 世界表没有分裂事件，生物不会自己生出后代；生态球里的新个体来自用户投放。分裂需要先在 Lean 里加一类守恒的邻格事件并证明仍是公理模型，作为下一步。
- **生物分解者**：尸体目前只靠物理泄漏分解（G26c 允许的两种之一）。
