# 语言身体搜索记录（2026-11-01 至 11-02）

这份记录回答一个问题：在同一条真实文本流、同一份内存和算力预算下，哪个身体离义务最近，并且便于继续修改。结论是 `context_cells`。它是第一个通过默认拒绝门的语言身体，但只是一个起点，能力边界见第 5 节。

实现：[cgb_language_candidates.py](../../scripts/cgb_language_candidates.py)；门：[cgb_language_gate.py](../../scripts/cgb_language_gate.py)；义务：[CGB_HARD_OBLIGATIONS.json](CGB_HARD_OBLIGATIONS.json)；Lean：[GenerationContextBody.lean](../../lean/CGBAxioms/CGBAxioms/GenerationContextBody.lean)；汇总：`results/published/cgb_language_body_search_20261102.json`。

## 2. 选择过程

`fading_cells` 的分支是逐项改动、每次重跑门得到的：

| 改动 | 结果 | 判定 |
|---|---|---|
| 尺度去掉递归 `fading_graded` | NLL 变好，O09 退化 | 不保留 |
| 只换成对数意见池 `fading_cells_pooled` | A_fresh 2.93→2.07，无退化 | 保留 |
| 意见池加混合尺度 `fading_mixed` | O09 退化 | 不保留 |
| 信任按说话 cell 数分组 | O21 3.14→3.13 | 假设被否 |
| 加低阶尺度，并按说话 cell 数分组 | O21 到 2.98 | 不够 |
| cell 加上下文签名 `fading_cells_matched` | O21 3.04，超预算 | 假设被否 |

两个针对 O21 的假设都失败后，我停下来做了分解测量：同样无容量限制的精确 0–5 阶计数，分别用级联和意见池读取。

| 读法 | 全部 | 新上下文 |
|---|---:|---:|
| 级联 | 1.677 | 2.528 |
| 意见池 | 1.564 | 2.402 |
| 意见池，信任按最长命中分组 | 1.551 | 2.313 |
| 1 MiB 表 | 1.668 | 2.522 |

读法没有问题，缺口在地址。随机储备池加符号哈希不能精确回到相同后缀，换成精确后缀后，O21 和 A_fresh 同时解决。

终选上的三个改动都没有增加通过项，都不保留：

| 改动 | 现象 |
|---|---|
| 再加 8 阶 | NLL 只好 0.013，超预算 |
| 计数上限 255 | O17 基本不变，否定了“旧证据稀释”假设 |
| 每地址 4 路 | 重访好 0.1，O17 变差 |

后两项说明有限预算下记得牢和换得快是真实的权衡，所以我在这里停止搜索，没有继续朝 0.02 这条线调参。

## 3. 门的修改

三处修改都因为发现门本身有漏洞，都对所有候选生效，阈值都不是看终选结果后放宽的。

- **O17 适应条款换掉。** 原来比较 OWT 验证集首尾窗口的趋势，但那里没有来源变化。标尺的超额损失在 −0.66 到 −0.84 之间波动，没有趋势，这个条款是在抛硬币。现在改成读另一真实领域文本前后，比较同一批未见字节的分数。
- **新增 O22。** `arbitrary_driven_tables_admitted` 证明单个暴露位点配任意表就满足全部公理，所以 O01 单独什么都不说明。现在要求事件触及的单元数有界，而且确实有未被触及的单元。
- **O03 改查最坏容量。** 原来只在流中段量一次，`context_cells` 的早期版本在 1.28 MB 时通过，到 300 万字节已长到 2.34 MB。现在查结构上可能达到的上限。这条也让 `fading_*` 失败：它们是按平均 cell 估算尺寸的。

门的区间参与了选型，所以另取三段文本重建标尺重跑，阈值不变。15M 这一段在搜索结束后才跑，只跑了一次。

## 5. 这个结果不说明什么

- **它不是生命，也不是通用智能。** 结构上它属于 PPM/PAQ 这一类上下文混合压缩器。O21 的胜出来自组合不同长度后缀的证据，没有语义，也没有学到的表示。
- **Lean 实例描述的是形状。** Model 的字段是自由函数。P2a 成立是因为每个事件都有边界参与者，P2c 成立是因为身份各不相同，这两条在这里没有实质内容。O02 的投影是平凡的恒等映射。实质内容是地址的局部性和写入保留顺序，`suffixOne` 只证明这些前提可以满足。Python 与 Lean 的对应靠测试检查，没有形式证明。
- **它只通过这 20 项义务。** 其余定理没有逐条对这个身体检查。新增 23 条定理的分类是 `draft`，尚未独立复核。
- **阈值是我定的。** O17 的 0.02、O22 和 O03 的容忍度都是工程选择，O03 还保留了此前所有候选共用的 1.25 倍容忍。
- **手工选择仍在。** 阶数、预算划分、意见池都是比较选出来的，没有必要性定理，也不是长出来的。它与 10-27“不手写神经系统”的方向还有距离。逆发育到现在没有给语言身体提供生成规则。
- **系统 4 没有接。** 没有动作，O19、O20 延期。
- **H/C/S 归属没做。** 这个身体没有 S 的对应物，慢权重只有计数和信任。

## 6. 对 11-01 记录的更正

- 个体实际读了约 392k 字节。684k 是两臂累计暴露量。
- 旧柱的 2.648 是已发布运行 A_fresh 段的在线分数，不是冻结诊断。
- 上下文写不是新想法，是 10-28 绑定写的恢复。证明的必要性是顺序分离，绑定写只是一种充分设计。
- 定理分层的旧数字 588/1054 作废，当时未列入的模块被算成了实例。
- 第一次全量审计的构建失败和今晚一次 `failed to read file ...olean`，都发生在内存紧张时，重跑可过。我判断是资源问题，没有进一步确认。
