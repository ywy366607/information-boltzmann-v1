# 可执行经历、自编辑与编译进权重

日期：2026-11-07。性质：研究方向与候选设计记录。用户要求保存本轮讨论，供后续推进；本文不替换现行身体、不启动新实验、不增加身体定理覆盖。

## 1. 要创造什么

让同一个语言生命体既能从经历中学习，也能把形成的规律、计划和内部操作组织成程序，执行、检验，并在有收益时编译成自身可复用的计算结构。

用户本轮补充：

> 而且模型可以自编辑，将自己想做的东西弄成程序然后编译进权重里都可以。

共同设想是：**经历可以成为程序约束下的数学对象；程序可以成为身体的一部分；程序运行的后果继续改写同一个身体。** 研究重点仍是最小生成与整体闭环：共享少量表达、执行和学习规则，让具体技能、记忆操作和调度方式从经历中形成。

这为既有公理—定理—机制—算法提供了一条可实现的候选连接：定理给出条件和可接受行为，机制对应可执行语义，算法实现同一转移，经验决定哪些构造值得保留和再次使用。

## 2. qwenputer 已经提供了什么依据

qwenputer 的公开实现把 CPU 电路编译成神经网络权重，用 Gated DeltaNet 递推状态充当 RAM。新增电路权重由编译器构造，原语言模型权重保留。其 RISC-V 路线使用新增的 11 层，程序、寄存器、程序计数器和数据可以装入递推状态；执行由连续前向微步推进。[官方项目](https://github.com/divagr18/qwenputer)、[RV32设计](https://github.com/divagr18/qwenputer/blob/main/experimental/riscv/docs/rv32.md)

必须区分两种同样可行、但用途不同的路径：

| 路径 | 权重承载什么 | 状态承载什么 | 修改方式 |
|---|---|---|---|
| 编译固定程序/电路 | 某个确定计算过程 | 输入、工作状态、输出 | 重新编译对应权重区域 |
| 编译处理器/解释器 | 通用执行规则 | 程序、数据、寄存器、运行位置 | 更新程序态，执行器权重可保持 |

qwenputer 的 CPU 加载程序主要体现第二条；其电路到权重的编译器同时说明第一条有实现基础。它的文档和检查提供了具体构造与数值证据；本项目尚未移植或独立复现。

### 2.1 为什么 GDN 能承担精确存储

采用键维度为行、值维度为列的约定：

\[
S^{+}=S+e_i\bigl(v-S^\top e_i\bigr)^\top.
\]

当保持系数和写入强度均为1、键为独热向量 \(e_i\) 时，第 \(i\) 行被覆盖为 \(v^\top\)，其他行保持。独热查询可以读回对应行。这给出存储器式操作；自然语言中的软地址、关联混叠和可学习门控则是另一种使用方式。[GDN电路说明](https://github.com/divagr18/qwenputer/blob/main/docs/q35.md)

其浮点精确性依赖专门设计的值域、位编码、阈值与归一化处理。复用时应保留这些数值条件，并检验所选后端和精度下的执行结果。[电路IR](https://github.com/divagr18/qwenputer/blob/main/chipformer/q35/ir.py)、[权重生成器](https://github.com/divagr18/qwenputer/blob/main/chipformer/q35/emit.py)

## 3. 经历升级为可执行数学对象

当前预训练分支已经有一部分基础：[pretrained_gdn_experience.py](../../scripts/ib_local/pretrained_gdn_experience.py)保存有限局部输入和当时的递推边界，读取时重新执行当前版本的原生层。当前误差因此能通过这次取用，更新旧局部计算涉及的门控和投影。

可执行经历可以概括为：

\[
\text{经历对象}=\text{适用条件}+\text{局部状态}+\text{可重执行转移}+\text{后果证据}.
\]

这是语义层面的候选形式，不要求立即新增四张表。各部分可以继续由同一连续状态、现有胶囊和共享算子承载。

- **转移可以共享。** 同类经历使用同一个程序/算子，只存不同的局部状态、参数引用和已观察区别，避免每条经历复制一套处理器。
- **状态可以是数学对象。** 连续激活、潜状态、向量间关系、有限映射、局部动力学状态，都可以作为操作数；不要求把因果经历降成字节原文或语义—突触对应表。
- **规律可以压缩成程序。** 当一组经历可由短程序及少量参数解释时，可以提出共同程序，再检验它能否重现相关后果、改善新经历上的预测和行动。
- **具体证据仍有位置。** 程序描述怎样变化，保留的状态与证据区分实际发生过的历史。压缩是否有效，要看所需区别能否在未来再次被使用。

候选主路径：

```text
真实经历 → 保留局部参与与后果 → 当下重激活
    → 提出可复用关系/程序 → 在新情境中执行与学习
    → 有效则巩固，矛盾则修正或释放 → 新经历
```

现行局部重算是保持历史边界的偏导路径，范围仍以实际执行为准；程序化表示可以扩展表达与重用方式，跨时间学习仍需实际的历史载体、当前结果和相应调制。

## 4. 模型自编辑的三种尺度

| 自编辑尺度 | 模型可以形成什么 | 对身体产生什么变化 |
|---|---|---|
| 程序态 | 子程序、计划、检索操作、事件安排 | 同一解释器执行新的状态转移组合 |
| 参数化操作 | 程序引用的可学习映射、门控、预测器 | 既有学习机制继续修改具体行为 |
| 编译权重 | 重复有效的程序对应的局部电路/子程序实现 | 新能力成为可直接复用的结构化权重区域 |

前两种适合经常修订、探索中的过程；第三种可作为反复有效过程的候选巩固方式。何时值得编译，应由后续使用收益、稳定性、描述长度及执行资源共同决定，不按固定次数机械晋级。

自编辑闭环为：

```text
身体发现需要/提出想做的事
    → 构造程序或修改已有程序
    → 核对类型、适用条件、资源与转移语义
    → 在可恢复的候选状态中执行
    → 编译到程序态或对应权重区域
    → 回到真实身体—世界交互
    → 根据真实后果保留、修订、释放
```

这里的“想做”来自身体自身的预测、经历取用和行动选择。程序不必全由研究者提供；初始提供的是有限的表达/执行基底及其语义，具体程序可以由模型提出。

编译电路的精确性需要得到维护。可学习接口、参数化算子与结构化电路分别确定编辑方式；对执行器本身的修改，也需要重新核对语义。这样可以同时保留可塑性与可靠执行，而不要求任意梯度扰动都保持电路正确。

## 5. Lean 如何进入身体的推理过程

希望形成的能力是：**在条件 \(P\) 成立时，按可靠规则得到 \(Q\)，并能继续把 \(Q\) 用于预测、计算和行动。**

可采用下面的分工，但这些角色作用于同一个过程：

1. 身体从经历提出对象、条件、关系和候选推理，决定当前要解决什么。
2. 程序执行器完成运算、规则应用和必要的证明检查。
3. 结论连同适用条件、来源或证明引用进入当前计算。
4. 世界后果校正经验前提、适用范围和后续取用方式。

Lean 的通常编译流程会擦除证明；把定理文件编译一次，不会直接得到能检查新证明的在线系统。在线推理需要把相关表达式当作数据，并实现检查/规则应用。可以从实际需要的有限语言与小检查器起步；已在离线验证的构造也可以提取为可执行操作。[Lean内核流程](https://lean-lang.org/doc/reference/latest/Elaboration-and-Compilation/)、[证明擦除与可执行布尔量](https://lean-lang.org/doc/reference/latest/Basic-Types/Booleans/)

逻辑保证的是前提到结论的推导；经验学习负责前提与世界的对应。一个可执行预测模型可以有严格的条件语义，其预测是否符合当前世界仍由实际后果结算。

### 5.1 现有 Lean 可复用的起点

先通过[定理索引](CGB_PROVEN_INDEX.md)核对原陈述及前提，不以名称计为身体覆盖。

=\llbracket P\rrbracket(x).
\]

这是拟建立的检验/证明义务，不是本轮已经完成的新定理。数值后端也需要实测对应关系。

## 6. 大小五行与内部时间

沿用[大小五行接口](CGB_NESTED_FIVE_PHASE_INTERFACE_20261105.md)：五行表示过程在情境中的作用，不规定五个物理部件。

| 当前作用 | 可执行经历/程序化后的候选形式 |
|---|---|
| 水 | 保存可再用的经历状态、程序引用、已结算后果与未结参与 |
| 木 | 取用经历，组合候选程序，预测执行后果 |
| 火 | 承诺并实际执行，使内部状态或对世界的接触发生改变 |
| 土 | 同一个身体、递推状态与执行过程承接这些变化，继续学习 |
| 金 | 在当前职责内检查条件与预测；在真实后果到达后结算收益、校准和保留 |

程序检查是相应情境中的辨别作用，不能代替世界回应后的实际收益结算。经历再次可用时，才形成下一轮水生木。

### 6.1 不同内循环可以有自己的时间尺度

内部执行能力可以维护各过程的逻辑时钟、待处理事件、运行位置、参数版本和后果归属。例如：

- 木在一次外界回应到来之前展开若干候选，必要时暂停并保留运行位置。
- 水中的某条经历在后果到达时重新激活，而不是每输入一个词元都重算全部经历。
- 金等待所需证据到齐，再把结算交回相应参与；版本引用帮助区分旧预测和新参数。
- 火可以及时接触世界，而未完成的内部计算通过有限状态继续携带。

执行器负责让事件交接和依赖关系正确；何时启动、继续、停止或让出计算，可以由身体从经历中学习。逻辑同步通过因果先后、事件与版本完成，不必把所有内循环强行锁成同一步频。

运行位置、计数器、事件队列、程序和证明数据都计入有限状态预算；使用有界表示与明确的满容量处理。每次外界事件间可执行的内部工作也有资源上限，以保留无限流所需的有界工作量。内部逻辑时间与真实CPU/GPU并行同步分别落实：后者仍需要对应运行时和执行后端。

## 7. 最小构造路线

1. **统一现有可执行经历的语义。** 从已经运行的局部胶囊和原生递推入手，明确输入、保持边界、当前参数引用、结果与信用路径。
2. **确定少量共享操作及其组合方式。** 优先复用现有读写、局部转移、重编码、条件检查和后果结算；让程序组合表达多种功能。
3. **让身体提出程序。** 先使程序在同一个闭环里被选择、执行、结算和再次取用，检验是否确实改变了未来行为和学习。
4. **再选择编译到哪里。** 程序态执行、原生CPU/GPU算子、结构化权重可以共享中间语义；按正确性和资源选择后端。编译进权重是可研究的实现方向，不预设为所有计算的最高效形式。
5. **形成自编辑与巩固闭环。** 当程序反复有效时，探索编译/缓存为更直接的结构；新证据仍能修订和解除。

每一步都以同一个身体—世界循环为验收对象，接口和数值检查服务于共同运动。当前RULER学习对照继续按其原登记执行；本文不构成新增训练、移植整套qwenputer或更换载体的指令。

## 8. 本轮形成的判断

qwenputer提供了“确定程序可以落进神经网络权重，递推状态可以承担程序内存”的具体实现依据。对本项目更重要的延伸是：**身体可以学习怎样构造程序，把经历形成的规律变成可执行对象，再把反复有效的程序巩固为自身结构，并利用同一执行能力协调多尺度内循环。**

这是一条把可塑性、条件逻辑、记忆压缩、自编辑与调度放到共同生成体系中的研究路径。目前记录的是方向、已有支点和待接的语义关系；相应身体收益、完整编译正确性与自编辑能力仍要在实际实现中建立。

**有启发，而且“程序约束下的数学对象”比单纯把经历表换成程序，更适合我们。** 它可以把三件事统一起来：可学习的经验、可靠的条件推理，以及不同内循环的执行调度。

### 1. 程序确实可以编译进权重。

qwenputer 把 RISC-V CPU 的运算电路编译成新增神经网络层，权重由编译器确定；寄存器、程序计数器、代码和数据放在 GDN 递推状态里。因此这里有两个层次：

- **权重实现执行规则**，相当于处理器。
- **状态保存程序和运行中的数据**，相当于内存。

换程序可以改状态里的代码，不必重新训练整个模型。[项目实现说明](https://github.com/divagr18/qwenputer/blob/main/experimental/riscv/docs/rv32.md)

它利用的正是我们熟悉的 Delta 更新：

\[
S^{+}=S+e_i(v-S^\top e_i)^\top
\]

当保持系数和写入强度都是1、键为独热向量 \(e_i\) 时，这一步精确覆盖第 \(i\) 行，其他行保持。这样 GDN 就能承担可寻址 RAM。[编译电路设计](https://github.com/divagr18/qwenputer/blob/main/docs/q35.md)

### 2. 经历表可以升级成“可执行经历”。

我们现在已经迈了一步：[当前经历实现](../../scripts/ib_local/pretrained_gdn_experience.py)保存局部输入和当时的递推边界，取回时用**当前参数重新执行本层计算**，让现在的误差修正旧经历参与过的门控和投影。

所以更自然的方向是：

> **经历 = 适用条件＋局部状态＋可重新执行的转移＋已观察后果。**

同类经历共享转移程序，只存各自不同的状态和证据。反复出现的规律，还可能压缩成一个程序或数学关系。

这里仍然需要保存具体经历留下的区别：**程序负责描述“怎样变化”，状态负责记住“当时发生了什么”。** 两者结合，才兼有压缩、重演和学习能力。

### 3. “把 Lean 塞进去”可以变成真正的条件推理能力。

我建议这样连接：

```text
身体从经历提出条件、关系和候选推理
                ↓
内部执行器应用规则、计算、检查证明
                ↓
得到带适用条件的结论
                ↓
结论进入预测和行动，后果再回来校正经验
```

Lean 负责保证“这些前提成立，则这个推导成立”；身体负责从世界里学习、检验前提是否适用。这就能获得你说的：

> 在 xxx 条件下，xxx 能推出 xxx。

有一个实现细节：**普通 Lean 编译会擦除证明，直接编译定理文件不会自动得到在线推理器。** 要在线验证新推理，需要把命题、证明表达式当作数据，并实现相应检查器。可以先支持我们实际使用的规则，再扩大表达范围。[Lean 的证明擦除说明](https://lean-lang.org/doc/reference/latest/Basic-Types/Booleans/)、[内核检查流程](https://lean-lang.org/doc/reference/latest/Elaboration-and-Compilation/)

而且项目已有起点：[RuleEncoding.lean](../../lean/CGBAxioms/CGBAxioms/RuleEncoding.lean)已经采用“固定解释器＋有限规则代码＋带条件的局部事件”，还证明了更新不影响参与范围之外的状态。可以沿这条线做可执行语义。

### 4. 内部 CPU 很适合协调大小五行的不同时间尺度。

它可以维护：

- 各过程的逻辑时钟、待执行事件；
- 尚未返回后果的参与标记；
- 参数和经历版本，避免把旧预测配给新结果；
- 暂停、继续，以及有限计算预算。

这样木可以多演几步，水可以隔一段时间重激活一次，金可以等后果到齐再结算，火仍能及时接触世界。**执行器保障交接正确，身体学习什么时候值得执行。** 不必给五相各写一个固定频率。

这解决的是内部的逻辑时间与因果顺序；真实 CPU/GPU 的并行同步仍由运行时落实。

**我的选择是：把它发展成“可学习身体中的可验证执行能力”。** 保留连续向量表征和现有资格信用，让经历逐渐成为带条件、可重演的数学对象；先复用少量共享操作与检查规则。qwenputer 给出了“这些操作也能落进权重”的具体范例，但它还没有验证我们这种可学习经历与信用闭环——这正是值得我们接着做的部分。

## 2026-11-13补记：让计算机原生执行身体已经确定的运算

用户提出：既然GDN可以表达RAM和CPU，能否直接使用真实CPU、内存、磁盘，避免在GPU神经层中绕一圈执行同样的逻辑？选型判断是：**连续神经表征学习关系和取用；已定义的精确程序由原生执行器执行，二者共有同一个持存身体。**当前统一SSD因果档案已经把外部存储纳入同体恢复，但仍未接入新的原生程序执行器。

qwenputer本身提供了具体的执行替换例子：其RV32实现可把HF电路层换成直接运行同一电路IR的Triton执行器；作者在6条记录上报告逐位置残差逐位一致，同一L4的电路步吞吐约250→3200 token/s。这里仍是GPU执行器，不能把它说成已在物理CPU上训练大脑；它证明值得借用的工程路径是**先固定同一转移语义，再选择更直接的执行后端**。[实现与逐位核验](https://github.com/divagr18/qwenputer/blob/main/experimental/riscv/docs/rv32.md#the-chip-layers-on-the-triton-executor-908fdd4)

对本体可具体表达为：R绑定对象与适用条件→选取/组合有限IR操作→原生CPU/RAM/SSD执行并返回带版本的轨迹与结果→原U依据真实后果修订同一个R。已知可微算子可提供VJP/JVP；离散选择沿用现有行动/后果信用。有限执行预算、读写范围、未结算资格和checkpoint都属于同一个身体，不把结果交给外部判断者替它决定目的。

把保持门和独热写入硬化只得到了RAM读写；指令语义、程序计数器与控制流仍要有对应实现。因而不需要将操作系统整体改造成神经网络，也不需要把本可原生执行的每次加法都模拟为神经层。真正待学习的是“什么时候、对哪个对象、在什么条件下，组合哪些转移能改善后果”；原生执行可承担确定的运算。此补记保留在原程序路线内，未增加实验、CPU子模块、内在目的或新的身体覆盖计数。
