# 原生果蝇运行时的无损存储与工作区优化

保留全部物理节点、原连接、浮点状态、突触迹、优化器与未完成信用。没有新增训练经历、妈妈调用或主线更新；32384主线继续暂停。135436573项来源—节点导数展开没有实现，也不作为原生学习的必要条件。

## 已落实

- KC/DAN树的内部索引使用经过范围检查的int32，解剖身份ID不变。
- 树系数只保留对角与按子节点索引的边系数；矩阵、求解器和伴随共用这些数组。边视图与比值不再各自保存一份完整数组。
- 空间场逐独立RHS传到CPU后再升FP64。求解和伴随仍使用FP64，输出仍为原dtype；取消GPU上的整场FP64副本。
- 私有RHS复用为树残差检查工作区，仍检查每个节点及1e-9相对残差门槛。此门槛是已有数值精度约束，不是生物参数。
- APL提供的88905节点/88900边森林也使用相同的精确树消元，避免通用稀疏LU的额外工作区。
- 紧凑事件布局与备用outgoing布局在CPU按块构造，保持原稳定排序、延迟和分块边界，只把最终紧凑索引上传。
- 未使用的incoming备用排列保留为原来的文件映射CPU执行元数据；实际走备用核时才搬到所需设备。
- 接收场先对实际接触归约，再按原延迟顺序加入唯一目标；不再为每个延迟展开两套全源×全节点零场。5HT工作区仅分配原方程实际读取的DPM行。
- 既有条件敏感度更新直接写最终行，取消重复整表拼接及中间乘积。没有增添新的导数路径，也没有替换原生突触资格迹。
- 仅在设备紧张且存在足够闲置CUDA缓存时释放闲置分配器缓存；保留全部活张量和状态。
- 在既有checkpointing开启时，KC末梢、DAN源释放与KC空间多巴胺算子按需重算；将物理状态及嵌套参数展平为真实checkpoint输入，避免闭包强引用整份历史。自定义伴随的CPU结果经`save_for_backward`进入同一存储协议，能够被重算钩子释放。保留同一局部BPTT与真实时钟，以计算换空间。
- CPU/GPU大语言头的有限性检查按张量视图分块，避免诊断检查自身申请几十MiB临时数组；不为检查展平复制非连续整表。

## 已验证的范围

真实KC树4184720节点、4180127边、四路存档GABA场（8977781个非零坐标）与原求解算术比较，FP32输出逐位一致。这个结果是空间算子一致性，不是全脑长期行为一致性的替代。

KC内部索引由167315312字节降至83657656字节，约159.56→79.78 MiB；每套系数缓存由133874296降至66955520字节，约127.67→63.85 MiB。

同一完整候选恢复后的PyTorch CUDA常驻分配由2468.989降至2273.132 MiB，减少195.857 MiB；这主要来自备用incoming排列延迟上传。该数字是恢复阶段分配量，不是完整训练峰值，也不包括全部驱动占用。

160项针对性检查通过，覆盖原稳定拓扑顺序、CPU/GPU备用路径、多个RHS与选择性梯度、稀疏/密集接收值和VJP、错误求解的残差拒绝、原生活动/信用/恢复接口。Deslice独立检查通过。完整套件未获认证。

## 尚未通过的资源验收

完整训练状态上的单拍前向及动作分数VJP已通过，VJP阶段PyTorch峰值分配2988.424 MiB；随后首次初始化语言动作头Adam二阶矩时申请148 MiB失败，驱动总占用已达4066.938 MiB。这次诊断没有完成优化器步骤，也不等于真实每词19拍或更长窗口的NLL训练准入。各次失败位置不同，不比较它们的峰值来估计BPTT额外成本。

已消除若干确定的浪费，但目前不能宣布4GB完整训练已可用。端到端训练吞吐也未验收；独立CPU算子计时口径不同，不作为加速比例。下一个已定位的优化对象是大型语言头优化器状态的存放与分块更新，需保持学习规则和完整恢复兼容；慢学习保持原生本地资格迹路线。
