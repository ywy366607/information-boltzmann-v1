# 碰撞算子（Boltzmann 型双体碰撞）

状态：设计已定，代码为可选项（默认仍是旧 MLP，已有个体加载不变）。证据标注为「测试」「短跑」「推导」，未证明的写在最后。

## 为什么重做

旧碰撞 = 默认初始化的 MLP 给每个旋转对出角度。测到的问题（Gen3 个体及 600 窗口对照）：

1. 速率约 0.17，每事件只转约 0.006 弧度，一个波寿命内累计约 0.15 弧度，几乎不作用。
2. Adam 一步只改参数约 lr，角度还要乘 dt（0.033），函数空间步长约比 decoder 小 30 倍。
3. 状态经 rms 归一化，振幅信息被抹掉，克尔型振幅依赖无法表达。
4. 旋转配对只在同一分量内的相邻通道，仅约 4 对跨分量，场与通量之间、通量轴之间几乎不交换，
   `collide` 文档里「通量轴参与、散射可改变传播方向」在实现上没有成立。
5. 碰撞没有「需要两个搭档」的约束：真空和单个波包也在转。

## 形式

每个旋转对 k 的角速率：

    rate_k = exp(log_phi_k) / T_x * kappa_k * c_h(k)

- `log_phi_k` 在 [log 0.3, log 10] 对数均匀取样（弧度/穿越时间），Mamba 的 dt 初始化同思路。
  `T_x = 1/speed_reference`（单位环面的穿越时间），初始分布与通道数、晶格、隐藏宽度、dt 无关（测试：C 33–513）。
- `c_h = (|field|^2 - sum_a |flux_a|^2)_h / (E_h + T_h)`，h 为头。单个行波为 0，真空为 0，
  两个波包相遇为 2–4 f1·f2（双线性），小振幅按振幅平方增长，大振幅饱和 ∈ [-1, 1]，不会发散。
- 不读位置（材料编码）、不读受体门控、没有阻尼；碰撞仍是正交旋转，能量与四个通道和守恒。
  耗散属于冷浴/响应。

旋转层：原 2 层相邻通道配对 + 3 层 `cross_groups`：把四个分量（场、通量 x/y/z）在同一通道上按
三种完美匹配配对，任意两分量之间有直接耦合。每个新层的配对数等于旧层，速率张量形状不变。
索引缓冲区必须在设备上（主机索引列表会让 CUDA graph 捕获失败）。

## 选项与预设

`collision_options`（均为可选，不给则完全是旧行为）：
`timescale, phi_min, phi_max, heads, kerr_std, coincidence, cross_groups, gram_input, pair_gate,
mod_gain, mod_bound, amplitude_input, center_receptors, position_rates, bed_rates, kerr_rates, kerr_only`。

训练脚本 `--collision-preset`：

| 预设 | 内容 |
|---|---|
| `boltzmann` | 双线性耦合 + 跨分量层。默认推荐。 |
| `boltzmann-mlp` | 同样的护栏包住一个可学习 MLP（输入只有每头 Gram 不变量，中心化到等分配）。开关，等长训练再评估。 |

`--collision-options` 的 JSON 会覆盖预设里的同名键。

## 已有证据

测试（`tests/test_collision_activity.py`，21 个）：旧默认的键和算术不变；真空/单波为零，两个波包才有；
小振幅按平方、大振幅有界；不读位置和门控；能量与通道和守恒；解析导数与有限时长流一致（含跨分量层）；
任意 MLP 权重都不能让真空或单包碰撞；对数调制有界；初始分布规模无关。

短跑（600 窗口，D=128，同一串文本，lr 2e-4 内含 60 预热/120 衰减，一个种子）：

| 碰撞 | 400–500 窗口相对词频先验的增益 | 秒/窗口 |
|---|---|---|
| 旧 MLP | 0.04（最后 100 窗口 -0.13） | 0.51 |
| 对数均匀 + 小 MLP / 克尔头 / 双线性 / Gram MLP | 0.39–0.41 | 0.51–0.75 |
| 默认预设 `boltzmann`（双线性 + 跨分量层，命令行预设实跑） | 0.404 | 0.58 |

结论：旧碰撞是因为太弱而不起作用，任何强度合适的形式都能补上；形式之间在这个预算下分不出高下。
速度：3 层跨分量旋转约 +13%（双线性 2 层 0.51 → 5 层 0.58，直接对比）；Gram + MLP 这一路再多约 +0.13 秒（0.58 → 0.71）。

### 速度优化的结论（试过且无效，不要重复）

- 用 PyTorch 小运算把 3 层跨分量旋转融合（取伙伴分量改 gather / 静态切片 + stack）：单独基准里没有更快（3.8–4.9 ms，原逐层 3.8 ms），
  因为 1 MB 张量上每个逐元素运算受显存带宽限制（约 16 µs，GTX 1650 约 128 GB/s），成本与遍历次数成正比，不是核数。
- `torch.compile` 包住整串旋转：单独基准 3.80 → 1.73 ms（2.2×），但训练器里完全没变化。逐核 profile 一次 CUDA graph 回放，
  编译开关打开与关闭的核表逐位相同（64310 次发射，GPU 核时间 437 ms，墙钟 464 ms）：训练器已经把介质事件整体用 inductor 编译，碰撞早已在融合核里，
  嵌套的 `torch.compile` 被外层吞掉。该开关已移除。
- 一次回放的 437 ms GPU 时间散在 6.4 万个平均 6.8 µs 的小核上（逐元素加 44 ms、乘 33 ms、拷贝 23 ms、小 gemv 约 40 ms、memcpy 11 ms），
  不集中在碰撞上。想显著提速需要整体减少核数，不是优化碰撞这一块。


## 没有证明的

- 非线性对预测是否有用：所有强碰撞形式增益相同，没有因果检验（不做适应后检查点的消融）。
- 状态依赖的幅度主要来自双线性门，不来自 MLP；MLP 权重 600 窗口内几乎不动，
  原因是梯度噪声（32 token/次更新，一致信号占比 0.06–0.07，噪声下限 0.042），不是梯度太弱
  （3e-5–4e-4，Adam eps 的 1000 倍以上）。要评估 MLP，需要更大批量或更长训练。
- 训练中场与通量之间的实际转移量没有测量，只有单元测试证明能力。
- 自克尔项（单个波包自己的振幅依赖转角）和克尔项的相位位移用途没有验证，代码里保留为 `_kerr_drive` 的第一列，默认关闭。
- 旧连续速度版本（碰撞因果性 +0.79 nats）的可比性：配对结构相同，但方向由控制器决定、输运沿被转向的方向走，现在没有。

## 失败模式记录

- 无界 `exp(g)`：mod_gain 3 + kerr_std 1 时速率到 1e6 弧度/时间，前向仍守恒，反向雅可比 ∝ 角度，
  第一个窗口结构信用出现非有限值。调制必须有界（`mod_bound`，默认 2，即最多 e^±2）。
