# 锁存要什么任务才看得出来：评测原则与任务设计（2026-11-03）

用户要求的诊断任务，不是准入检验。动机：OWT 上 NLL 看不出锁存的作用（`results/cgb_feedback_birth_20261103/RESULT.md`），而 OWT 本身也许不需要锁存：需要的信息若在 512 字节窗口内，模型自己学慢一点忘就够了。

## 1. Qwen3.8 报告怎么说 NLL 与下游

依据技术报告（arXiv 2608.30320）：
- 摘要与 §1：损失与下游准确率“不总是一起动”，两个方向的分歧都观察到。
- §2.2：动态与静态残差读写的损失差只有 0.002，基准差距却很大，“只看损失会低估这项改动”。稀疏残差写入在预训练损失和基准上几乎无影响，后训练后质量下降，“只看预训练指标会做出错误决定”。
- §2.1.1：RoPE 与 NoPE 预训练几乎没差别，后训练后 NoPE 无尽生成的比例高得多。
- §2.3.2：n-gram 词表越大损失越低，下游不跟随。
- 消融的评测集：知识（MMLU、MMLU-Pro、SuperGPQA、C-Eval、CMMLU）、数学（MATH、GSM8K）、推理（BBH）、多语言（MMMLU）、代码（EvalPlus、MultiPL-E）、域外困惑度；长上下文用 RULER（4K 至 1M）和 8-needle MRCR（128K 至 1M）。
- 取舍没有单一公式：损失 + 下游 + 效率 + 稳定性，下游与后训练/长程行为可以推翻小的损失差。

对本项目（76.5 万参数、256 万字节）可借的：知识类基准在这个规模全是零（LAMBADA 准确率已经是 0），能借的是三类：
1. **长上下文检索**（RULER/MRCR 的同类）：下文 T1–T3。
2. **长程生成行为**：自由生成时的重复与卡死比例（Qwen 发现 NoPE 的无尽生成）。锁存尤其要查这一项，强的自持状态可能把生成锁进循环。
3. **域外困惑度**：换语料（代码、其他语言）看是否只是记住了 OWT。

## 2. 任务

全部嵌在真实 OWT 字节里，记录格式 `\n[#Kq7 = mango]\n`：键是 62 字符取 3 个，值从文本里最常见的 512 个 4–8 字母小写词里抽。实现：`scripts/ib_local/recall_task.py`、`scripts/ib_local/eval_recall.py`，训练用 `train_gdn_fast_table.py --stream recall`。

- **T1 间隔召回（已实现）。** 事实出现，隔 G 字节普通文本，查询以同样格式重复键，值只能靠召回。训练时 G 在 [16, 448] 上对数均匀，通常落在一个 512 字节信用窗口内；评估 G ∈ {16, 64, 256, 1024, 4096, 16384}，新键、未见文本、冻结权重、状态延续。G > 512 时，训练里事实和查询从未同处一个信用窗口，就是“短窗口训练、长距离推理”。
- **T2 带干扰的召回（待做）。** 事实与查询之间插入 m 条其他事实。非锁存的 delta 记忆在同一地址附近被冲刷，锁存若能把重要条目压住应退化更慢。
- **T3 提示前缀（待做）。** 段首给一条“设定”（如 `[mode: amber]`），之后整段内多次出现 `[mode?` 要求复述，间隔可到上万字节。设定反复有用，学习者应学会把它长期压住；这是“重要前缀放进锁存”的直接检验。

## 3. 预测

1. T1：G ≤ 448 时两组都能部分召回；G 越过 512 后，无锁存组按 α 的连乘衰减，锁存组退化更慢。若两组同样衰减，说明锁存没被用来存键值（读出关系有问题，而不是信用问题）。
2. 快表组在所有 G 上召回都很强（同一上下文首次写入即得 1/2 权重），作为“记忆存在时可达到的上限”。
3. 锁存组若在 T1 上占优，再做 T2、T3 和生成卡死检查，才谈得上它是否值得留在身体里。
