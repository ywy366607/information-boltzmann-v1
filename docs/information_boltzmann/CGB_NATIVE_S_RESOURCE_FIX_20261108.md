# 原生S资格接入：主机提交压力定位与资源修复

本轮只处理既有桥接训练和资格接入的工程故障。主源仍为524更新、seen450757、next_case14待反馈；只在可丢弃研究分支执行。资格K、参与归属、128词元窗口、CE/SIGReg、FP32 master与Adam均不因资源诊断而改变。保持／再学习三臂尚未启动，生产区和身体定理覆盖增加0。

## 报错位置与监测证据

原四次失败分别在LLVM主机分配、缓存调试IR读取、CUDA模块加载、以及伴随分配失败的Adam/CUDA unknown处。不能由最后一个报错函数倒推根因。

新增独立外部监测器`scratch/bounded_causal_tags_20261108/probe_native_s_resources.py`：记录Windows系统提交总量/上限/余量、进程PrivateUsage与RSS、NVML全卡显存；工作进程记录模型加载、内核模块、普通反向、Adam等阶段。外部采样不依赖LLVM是否释放Python GIL。仅终止本监测器创建的子进程，不操作其他任务，不调整分页文件或清理用户缓存。

`resource_probe1`在系统提交余量约457 MiB时保护退出，全卡使用约2.11 GiB、仍余约1.89 GiB；退出前已经加载272个Triton内核，包含自动调优候选。多个后续受监测探针同样在显存仍有余量时触及提交阈值。保护退出不是一次新的CUDA分配失败。

采样期间系统提交上限动态变化，不能把某次Torch显存统计、物理空闲内存或固定保护阈值单独视为可用总额度。C盘最少仅余约650 MB、分页文件位于C盘且由系统管理；后续空闲量变化也被记录，本轮没有修改OS设置。

## 两项显式资源候选

1. `triton_bounded_autotune.py`从原后端已剪枝的合法配置中，按较少warp/stage选一个，再进入原生单配置执行路径。只将`prune_configs`缩成一项仍会测速，仍分配256 MiB清缓存缓冲区；新实现跳过此测速。原CUDA资源检查和内核源码保留，未宣称这是最快配置，或与旧自动调优配置位级一致。所有未来对照须采用同一策略。
2. `readonly_checkpoint.py`对可信本地检查点建立真正只读的CPU文件映射，将原storage交给同一个Torch zip反序列化器。当前Windows默认`torch.load(mmap=True)`采用私有写时复制映射，仍占系统提交额度。只读输入必须通过现有restore复制到可变学习状态后再更新；不使用可写共享映射，不原地修改源张量。该候选依赖当前Torch私有加载API，默认关闭，已检验值、别名、步幅、生命周期及复制后更新。

Microsoft说明写时复制视图会为整个视图计入提交量：[MapViewOfFile](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-mapviewoffile)。本机实测另见`readonly_checkpoint_actual_comparison.json`：遍历真实检查点的57,820个张量项（含共享历史的重复访问），全部值、dtype、shape、stride一致；只读加载增加约38 MiB进程PrivateUsage，随后原写时复制加载另增加约683 MiB。不是加载了57,820份独立物理存储。

候选入口`run_native_s_credit_retention.py`增加`--bounded-autotune`和`--readonly-checkpoints`，默认均关闭；配置和执行源码哈希写入准入报告，run阶段继续要求与准入配置一致。原11份执行源码不修改。没有把新的资源开关写成资格学习或新奖励机制。

## 完整准入

`resource_fixed_admission2`完成桥接及两新窗：525/526/527更新中，526的S调制范数34.364、空资格新增0；527的S调制范数17.344、原始旧信用与实际FP32添加范数均约0.00173544。持久数组4,325,592字节；含pending捕获为11,677,976字节，另计显式工作区21,809,024字节，完整上界约31.94 MiB，低于64 MiB上限。没有资格误差/余弦门。

`resource_fixed_admission3`进一步发现比较本身的额外开销：除约805 MB的更新前检查点，又保存并映射约1.30 GB的完整更新后终态，外部监测器因物理空闲低于1 GiB保护退出。该退出也不是资格或CUDA公式失败。

为避免只为比较而增加完整终态副本，`checkpoint_digest.py`逐字段计算完整状态的规范SHA256，记录dtype/shape/stride及全部值，覆盖参数、优化器、S、经历、pending、RNG和资格；共享张量视图在同一次冻结遍历中复用已算摘要。仍完整保存更新前检查点、分别从磁盘恢复两次并执行真实第三窗，对比两个完整终态摘要及未计时的窗口指标。不比较单个NLL代替状态，不改变学习规则；没有宣称密码学摘要是Lean中的形式化等式证明。

`resource_fixed_admission4_digest`发现摘要器未覆盖资格布局中的slice元数据，已补齐并新增检查。之后先在实际候选上离线遍历全状态：4,311个张量项、2,565个唯一张量视图、最大单张量缓冲4 MiB，CPU检查通过，才重跑GPU。

最终完整入口在`results/cgb_native_s_credit_20261108/resource_fixed_admission5_final/`运行。最终结论以该目录的`admission/report.json`和外部`supervisor.json`为准；本节下方补记完成结果。旧失败及保护退出目录保持不变。
