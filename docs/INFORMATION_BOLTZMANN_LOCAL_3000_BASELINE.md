# 局部碰撞短训基线：3000 次更新

用户于 2026-09-11 授权优先训练可供测量的新模型，预算 3000 次更新；明确选择出生分布＋局部碰撞。本次授权覆盖训练接入和必要执行优化，不等待全部研究测量模块完成。

## 本轮固定模型

- 数据：现有固定 OWT 文档划分，GPT-2 BPE 50257 词表。训练流不绕回，验证集独立；不用测试集选权重。
- 正式配置：N=256、相空间维度 4+4、语言隐层 H=128、碰撞 Attention Hc=32、每 token 四个动力学子步；每次更新至少 128 token。
- 出生：BOS 条件下产生一次粒子分布。输入编码为无 dropout 的 Attention＋MLP；四层仿射耦合，平移无 tanh，log-scale 为 0.6r/sqrt(1+r²)，末层小权重初始化。BOS 单 token 不检验多 token Attention 的优势。
- 持存：后续输入沿已有外力路径进入，同一粒子状态持续演化，更新边界只 detach，不重采样出生。出生专有参数仅首次窗口获得路径梯度；不能将此称为每 token 的 X→f 注入算子。
- 碰撞：严格局部三角核 h=1，Bmax=1；均匀 pair、单位球面法向、完整无截断 Poisson 候选；八元素对称轨道 Attention 学习接受率。弹性反射保持粒子数、动量、动能。
- 加速：CPU 批量生成与调度全部候选，整个窗口仅批量传送索引、法向和随机阈值；同层无共享粒子的事件在设备上并行。背景位置速度保持子步开始时的值且保留梯度。缓存背景 K/V；位置中心平移从 V 显式扣除，K 的平移在 softmax 中抵消。
- 梯度：窗口内完整路径反传及因果 Bernoulli log-prob 前缀的似然比项，常数 baseline=log(vocab)。原始 CE 与训练 surrogate 分开。

## 交付与测量

保存真实 update、token cursor、前一 token、物理时钟、状态、优化器、NumPy proposal RNG、Torch CPU/CUDA RNG、源代码与数据清单哈希。每 250 步独立冻结验证并保存 age/last/BBest。BBest 按验证 NLL 最小选取。

监控包含 NLL、梯度范数、相空间协方差/特征值、位置速度各轴方差、动能势能、gamma 分布、候选数与实际碰撞数、完整更新时间和显存。动力学快照供离线测量，不能凭稀疏快照推断高频波谱。

性能以真实完整更新实测；不把 CPU 数值通过写成 GPU 性能达标。3000 步是预算终止，不预先声称收敛、临界或无限持存。完整离散能量账与响应谱随后对该基线的测量副本执行。

## 本轮接口检查

已有串行、DAG、两事件路径梯度审计，加上设备批量路径相对串行的 FP64 值/梯度核对、出生流逆映射及窗口因果性检查，共 42 项于最终接入时通过。后续更改须更新验证记录。

## 正式运行

目录 `results/ib_local_bpe_256_3000_v2`，启动进程 PID 30404，监控 PID 25280（仅用于本次运行定位，重启后会变化）。每更新 128 token，预算 3000 更新＝384000 token。旧全局 Slice 对照保存到 `results/ib_bpe_512_5000/age_002500.pt` 后暂停，可独立续训。

```powershell
python -m scripts.ib_local.train --data data/ib_owt_gpt2 --output results/ib_local_bpe_256_3000_v2 --steps 3000 --tokens 128 --particles 256 --hidden 128 --validation-tokens 4096 --validate-every 250 --compile-evolve --pad-candidates --block-graph --small-workspace
```

最终检查 42 passed。256 粒子的较紧填充校准中，完整回放更新约 1.32 秒、峰值张量分配约 1034 MiB；这不是正式 100 次性能验收。正式配置增大常用填充余量到 (64,32,8,4,2,1)，减少随机表溢出导致的慢回退；需以实际日志再次报告速度和全进程显存。候选超过这些容量时完整执行，不截断。只有标准容量窗口用于捕获，溢出窗口不覆盖常用图。

执行优化包括：每子步编译、完整更新 CUDA Graph、缩小 cuBLAS 工作区、保留子步重计算以满足整进程显存预算。窗口边界状态重新成为独立梯度叶子，以固定编译签名；仍无跨更新梯度。首窗口保留出生流的梯度。源码副本随运行保存，所有随机数状态写入 checkpoint。

恢复时在上述配置基础上追加 `--resume results/ib_local_bpe_256_3000_v2/last.pt`。目标 steps 仍为总更新数 3000，而不是再训练 3000 步。

## 运行修正记录

第一次正式尝试 `results/ib_local_bpe_256_3000` 在完成 16 次更新后，于第 17 个随机候选表的溢出回退期间 OOM。它不是有效的 3000 步结果；已单独标记为失败尝试。此前约 1.32 秒的校准只测了少量更新和张量显存，没有覆盖整进程显存与该回退路径，不能据此宣布验收。

修正后采用新目录 v2 从出生重新开始，不拼接失败尝试的数据。回退前显式释放 CUDA Graph、梯度引用和缓存，完整处理溢出候选；下个常用形状窗口再建立图。前 50 步每 10 步保存恢复点，其后每 50 步保存。监控同时记录当前张量分配、保留池和全卡显存。此修正需以实际越过第 17 步及后续运行验证。

cuBLAS 与 cuBLASLt 的工作区为分别配置的资源；配置依据 [PyTorch 2.9.1 实现](https://raw.githubusercontent.com/pytorch/pytorch/v2.9.1/aten/src/ATen/cuda/CublasHandlePool.cpp)，设置小工作区并统一使用。实际显存仍以进程测量为准，不能只看张量计数器。

## 最终执行方式（覆盖前述全窗口图试运行）

使用 `block_graph.py` 的可复用 8-token 图，保留完整 128-token 梯度链。块之间不 detach，损失和似然比前缀仍在整个 128-token 窗口计算。每块通过重入 checkpoint 在反向前重放，输出与返回梯度都复制，防止下一次图回放覆盖缓冲。溢出只让对应小块按完整候选表走普通执行，不丢事件、不重新编译罕见形状、不销毁其他小块图。

已做独占 GPU 审计：连续复用、跨块状态/参数梯度、两次参数更新，以及普通溢出块与图混合执行，均对照原窗口通过 FP32 atol=2e-5、rtol=2e-4。CPU 原检查 42 项通过。

从完整 checkpoint 50 继续，当前 PID 30404，运行目录仍为 v2。通常约 1.85 秒/更新；实测全卡 653 MiB、GPU 99%。与 1.5 秒目标仍有差距，按用户最新“优先得到3000步基线”的要求继续训练，不以早期校准冒充性能达标。具体更新数以实时 progress.json 为准。

各次恢复都保存独立源码副本。原始日志存在恢复前未保存更新的重复步号；统计曲线按 `(kind, step)` 取最后一条，不计为新增训练数据。`last.pt` 保存恢复边界，`BBest.pt` 每250步按独立验证选择。
