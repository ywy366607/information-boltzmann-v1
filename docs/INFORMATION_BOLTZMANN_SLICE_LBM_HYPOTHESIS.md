# 研究观察：Transolver Slice 与 LBM 速度通道

2026-09-10，用户提出：“Slice 看起来很适合当作 LBM 的离散速度通道。”记录为后续研究假设；不修改正在训练的个体，不视为既有算法等价或已经验证的加速。

## 联系的核心

两者都将大量局部信息组织到有限通道，在通道间处理后回到原来的场。候选映射为：SliceRead作为自适应投影/求积，Slice交互作为通道碰撞或弛豫，Deslice作为重构/回写；另外显式定义与速度相容的输运。

仓库当前Slice是全分辨率视觉场上的瞬态聚合工作空间，不能直接等同于每个信息位置x处的速度人口f_i(x)。视觉场X的像素坐标与Information Boltzmann的信息位置x也不是已经对齐的同一个空间。原有Slice/Deslice没有自动赋予通道速度c_i、非负概率质量、速度求积权重或沿c_i的输运。

## 三种可区分的候选

1. 将通道明确约束为离散速度/求积节点，学习其投影与受约束碰撞。此路线需要重新讨论“速度不离散”的原始要求；不因本记录视为已授权放弃该要求。
2. 保留连续v与粒子，仅让Slice成为速度分布或碰撞算子的自适应低秩积分基。有限个计算通道不等于有限个允许速度，可能兼顾连续速度与GPU矩阵计算。
3. 学习质量/动量/应力等矩通道，在矩空间进行闭合与弛豫，再重构更新。这需要检验矩闭合误差，不能将均值特征当作完整分布。

## 必须补齐的结构

- 定义通道表示质量、均值特征、矩还是基函数系数；当前归一化特征平均不是概率质量。
- 定义通道与速度的对应及输运：标准速度通道的传播依赖c_i，普通Deslice回写本身不自动构成这一传播。
- 质量、动量、能量的保持分别需要约束；softmax权重归一化不能自动保证动量、二阶矩或碰撞熵耗散。
- 若通道/求积节点随输入或时间变化，需计入重投影和基变化造成的输运与矩误差，不能把换坐标误报为物理碰撞。
- 保留当前仓库的完整场、瞬态Slice和Slice/Deslice写入路径；任何后续跨项目统一都需单独论证，不在本观察中合并计算图。

## 后续判断标准

先明确以上三条中的哪条数学路线，再验证输运、矩与重构性质；随后在专业真实数据集上充分训练，比较端到端耗时、显存、预测质量及同一个体的长时行为。不能仅从矩阵形式承诺加速，也不能以瞬时重构相同代替多时刻行为保持。

参考：现有实现 fine_grain/native_mot.py 的SliceRead/DesliceWrite；架构约束 docs/NORTH_STAR.md。LBM离散速度与Hermite求积关系：https://arxiv.org/abs/comp-gas/9712001 。


## 后续加速研究顺序（2026-09-10 用户指示）

当前 5000 更新的 OWT 个体保留为动力学与训练基线，完成研究后再实施加速候选。速度和可扩展性也是研究可行性的要求：后续应能研究 1024 个粒子，而非仅在 32 个粒子上展示运行。当前 GPU 利用率及宽度校准提示串行调度/小算子开销，但尚无完整 profiler 分解，不把碰撞或积分器预先认定为唯一瓶颈。

1. 在保存的真实 OWT 状态副本上测量前向驱动、碰撞（含注意力/密度查询）、积分、反向、优化器、CPU/GPU 同步、日志、可视化、检查点与诊断分别的耗时。GPU 使用事件计时或 profiler，区分异步提交和实际执行；报告预热后吞吐、编译冷启动及端到端总时间。记录碰撞尝试数和接受率。分析不扰动原个体的状态与 RNG。
2. 先尝试保持现有数学法则的工程优化：减少同步与 Python 调度、融合算子、固定形状编译、向量化相互独立的工作。共用粒子的顺序碰撞不可直接改成同时更新并声称法则不变。编译收益必须扣除启动成本，混合精度单独验证能量账目和梯度误差。
3. 只有热点证据支持时再比较结构性替代：Slice 低秩碰撞、局部/稀疏相互作用、离散速度 LBM 或受约束矩闭合、结构化积分器。固定特征宽度时，N 粒子到 M 个 Slice 的聚合/回写与通道注意力典型成本为 O(NM+M²)，但若精度要求 M 随 N 增长则不能宣称固定线性成本；原始抽样碰撞也不自动是 N² 算法。标准 LBM 保留每个空间格点的 Q 个速度人口，并非把全空间压成 Q 个全局 token，高维位置网格本身可能爆炸。
4. 扩散模型启发优先考虑已知线性部分的解析处理、指数/分裂积分及减少昂贵非线性评估。当前 OU 子步已有解析更新，DPM-Solver 的扩散 ODE 结构不能原封不动套用。改变步长、噪声或碰撞安排需检验多时刻路径统计，不以相同单时刻分布代替长时记忆保持。
5. 后续运行规模阶梯 N=32/64/128/256/512/1024；先做真实 OWT 的运行成本检查，再对有希望的候选充分训练。固定物理参数、粒子权重归一化、每粒子碰撞率/交互预算的含义并记录；不能靠减少每粒子演化工作伪装扩展性。逐档量显存并留余量，超预算标记不可行，不直接启动可能 OOM 的最大档。该成本阶梯不是能力或物种标度结论。
6. 同时给出固定数据/更新预算和固定墙钟预算比较。代价表必须包含 token/s、每 token 延迟、峰值显存、完整研究周期耗时、验证 NLL、守恒/能量账目、年龄局部响应与相关时间、组织结构及稳定性。比较多个通道数/容差的速度—误差曲线，不以 GPU 利用率或单个核函数倍速判胜。先明确可接受的科学误差，保留无法由验证 CE 替代的个体动力学指标；近似算法改变了哪些物理性质须显式报告。

方法来源：Transolver https://arxiv.org/abs/2402.02366 ；DPM-Solver https://arxiv.org/abs/2206.00927 。这些是候选启发，尚无本系统的加速实测或等价性结论。
